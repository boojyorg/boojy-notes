## The short list

If only a dozen things get fixed from this document, these are the twelve. Each one either
loses user data, destroys structure in a file, crashes the editor, or makes an everyday
keystroke do the wrong thing.

1. **Forward Delete at the end of a block, then Enter, crashes the editor** to the "Something
   went wrong" screen (§1.8, live). Cut over a selection that spans two blocks does the same.
2. **Enter in a delete confirmation deletes, even though Cancel has focus** (§4.1, live).
3. **Enter or Shift+Enter inside a table cell breaks the table on the next open** (§3.1, test,
   found independently twice).
4. **Clicking into a callout and out strips its bold, links and code from the file** (§3.2, test).
5. **Find → Replace changes the file but not the screen; the next keystroke writes the old text
   back** (§3.3, test).
6. **An outside delete of any note while you are typing brings the file back and rewrites the
   whole vault** (§2.1, test).
7. **A revert in git, Obsidian or Time Machine to bytes the app once wrote is dropped as an echo
   and then overwritten** (§2.2, test).
8. **Saving a note inside a folder Finder allowed (`Work: Client`, a trailing space) moves the
   file into a new sanitised sibling folder** (§2.3, test).
9. **Enter at the end of a code block does nothing, and pasting several lines into one does
   nothing either** (§1.3, §1.10; live and test), so code cannot be typed or pasted into a code
   block.
10. **Typing straight after a `[text](url)` link drops the next character**, and typing a
    `#tag` then a space swallows the space and glues the next word on (§1.1, §1.2, live).
11. **Rename from the ··· or right-click menu does nothing** (§4.2, live); only double-click
    renames.
12. **On `pnpm dev` only, typing after editing the title drops characters** (§1.15, test, 12 of
    12 runs; the production build is clean). Not a user bug, but it will send someone hunting a
    phantom on the surface Tyr judges the editor on.

Three decisions sit behind several findings and are worth taking once:

- **Every native edit over a selection that spans blocks has to be intercepted** (§1.8, §1.9).
  `handleCrossBlockKeyDown` catches Backspace, Delete, Enter and printable keys; forward Delete
  at a block end, Cmd+X, Shift+Enter, the formatting shortcuts and URL-paste-over-selection all
  reach Chromium, which merges or splits React-owned block roots. The result is either a crash
  or a screen that no longer matches state. One guard at the top of the keydown path, plus an
  `onCut`, closes the class. The same audit should cover `getBlockFromNode` returning
  `el: undefined` for every ref-less block (table, code, callout, image, file, embed), which
  three handlers dereference after `preventDefault` (§1.10).

- **Raw `setNoteData` bypasses history and is silently reverted while a text commit is
  pending** (§2.4). The keystroke ref stops syncing from state during the 300 ms commit window
  and is then republished wholesale, so any state change made in that window by a raw setter is
  undone, and any raw setter is invisible to undo. Sidebar move, block drag, the file-deleted
  rebuild and the vault switch all use the raw setter. Route them through `commitNoteData`, or
  have the flush merge rather than republish.
- **Cmd+K is bound twice** (§1.6). The editor's link shortcut and the search palette both fire.
  One of them has to move; see the UI section for the recommendation.

## 1. Editor: typing (1.1–1.7 live in the walkthrough; 1.8 live; the rest test)

### 1.1 Typing after a Markdown link drops the next character — correctness, live

Type `Link test [x](https://a.b)` then ` after`. The screen reads `Link test x↗ fter`: the `a`
is gone. In an earlier run ` and` became `and` (the space went instead). The link is converted to
an anchor on the closing `)`, the block repaints, and whatever is typed in the next beat is lost
between the repaint and the caret re-anchoring. Root cause not pinned; start in
`useInputHandler` where the `[text](url)` conversion repaints the block, and check whether the
caret lands on the `CARET_ANCHOR` before or after the next `beforeinput`.

### 1.2 A typed `#tag` eats the space that ends it, and Enter after it is captured — correctness, live

Type `Tag test #alpha` then ` beta`: the text becomes `#alphabeta`. In a second run
`#tagone here` became `#tagonehere`. The backlog lists "TagMenu swallows the space that ends a
tag" under technical debt; in practice it merges words, and because the caret is then still
inside the tag the suggestion menu stays open, so the Enter that should start a new paragraph
completes the tag instead and the `/` typed next lands mid-paragraph with no slash menu. This
is a typing bug, not debt. Fix: let the space through (`TagMenu`'s space dismiss must not
`preventDefault`), and only let Enter complete when the user has arrowed to a suggestion or the
typed text differs from the highlighted one.

### 1.3 Enter at the end of a code block does nothing — correctness, live, root cause found

`src/components/CodeBlock.jsx:76` derives the controlled textarea value with
`block.text.replace(/^\n+|\n+$/g, "")`. Enter's handler writes `text + "\n"` to state; the next
render strips the trailing newline back off, and the caret sits where it was. Enter in the
middle of the block works, which is why it has survived. Shift+Enter is the same. Side effect:
a fence that begins or ends with blank lines in the file loses them on the first keystroke,
because `handleInput` sends the stripped value. Fix: stop stripping in the render path; trim
only when serialising if that is what the fence needs.

### 1.4 Code-block undo is one character per Cmd+Z, and every keystroke re-renders the editor — correctness/perf, live

`updateCodeText` goes through `commitNoteData` → `pushHistory` on every keystroke
(`useBlockOperations.js:174`), where text blocks coalesce over the commit debounce. Typing
`abcde` and pressing Cmd+Z once gives `abcd`. Fifty characters of code evict every earlier
structural undo entry (stack cap 50), and `haveEditorBlockRenderChanges` treats code text as a
structural change, so each keystroke re-renders every block. Table-cell and callout commits use
the same path, but only on blur. Fix: route code text through `commitTextChange` (or a
debounced equivalent) and drop code text from the structural comparator.

### 1.5 Slash menu → Code block (and Callout) puts the caret *below* the new block — UX, live

`replaceWithSpecialBlock` in `useSlashCommands.js:36` deliberately inserts an empty paragraph
after the block and focuses that. For a divider or an image that is right; for a code block or a
callout it means the thing you asked for is empty and your typing goes into a paragraph under
it (in the walkthrough two lines of code landed as two paragraphs). Put the caret inside code,
callout and table; keep the paragraph-after for divider and image.

### 1.6 Cmd+K opens the link popover and the search palette together — correctness, live

`useKeyboardHandlers.js:462` binds Cmd+K to the link editor; `useAppKeyboard.js:109` binds it to
the palette. With the caret in the editor both fire: the palette opens over a link popover that,
with a collapsed selection, positions itself against the editor's origin and pokes out from under
the sidebar edge as a teal chip reading "…ply". Escape closes both. Decision needed; see the UI
section.

### 1.7 Smaller, live

- **Leading spaces in a paragraph are stored as U+00A0** (`  return a;` became `&nbsp; return
  a;`). Same family as the known trailing-space case; Chromium writes the first of two spaces as
  a non-breaking space. Worth handling in the same fix.
- **The `/` menu only opens at the start of an empty block.** Mid-line `/` types a slash. That
  is a defensible choice for a quiet editor, but Notion, Craft and Obsidian all open it after a
  space, and the hint column now makes the menu the discoverable path. Listed under UI thoughts.

### 1.8 Forward Delete at the end of a block crashes the editor on the next edit — data-loss, live

There is no `Delete` branch in `handleBlockKeyDown`. Chromium merges the next block's text into
this one (wrapped in an inline-styled span) and removes the next block's element; `input` fires
and the merged text is stored for this block, but the next block stays in state. On the next
structural commit React calls `insertBefore` against the missing node and throws
`NotFoundError`; the `ErrorBoundary` takes over with "Something went wrong". Reproduced:
`first` / `second` / `third`, End in `first`, Delete, Enter, crash. Until the crash, state holds
`second` twice, so a save in that window duplicates text.

### 1.9 Cut, Shift+Enter and the formatting shortcuts over a cross-block selection corrupt the DOM — data-loss, test

`handleCrossBlockKeyDown` (`useKeyboardHandlers.js:387`) intercepts Backspace, Delete, Enter and
printable keys only. Cmd+X (there is an `onCopy` but no `onCut`) and Shift+Enter reach Chromium
and produce the same merged-span-plus-orphan-state shape as 1.8, crashing on the next Enter.
Cmd+`, Cmd+Shift+S and Cmd+Shift+H run *before* the cross-block check (`:433-461`) and their
`extractContents` / `insertNode` fallback splits both block roots into duplicate-id clones (four
elements for two ids); the text survives only in orphans that the next repaint removes. Cmd+B and
Cmd+I over a cross-block selection format both blocks on screen but re-read only the anchor block
into state, so the second block's bold is never saved and any repaint erases it. URL paste over a
cross-block selection inserts the `<a>` as a direct child of the editor div.

### 1.10 Handlers dereference `info.el` for blocks that never register a ref — data-loss, test

`getBlockFromNode` returns `el: blockRefs[blockId]`, undefined for table, code, callout, image,
file and embed. Three callers dereference it after `preventDefault`. Two user-visible casualties:
**multi-line paste into a code block does nothing** (`CodeBlock` stops keydown and input but has
no `onPaste`, so the editor's handler owns it, throws on `selectNodeContents`, and the textarea
stays empty; table cells and callout bodies the same), and **a selection extended from a
paragraph into a table cell, then Backspace, removes the table from the DOM but not from state**,
after which the file keeps a table the screen no longer shows.

### 1.11 Enter and Backspace placement — correctness, test

- **Enter at the start of a heading demotes the heading text to a paragraph** and leaves an empty
  heading above it (`insertBlockAfter(…, "p", afterText)` keeps the type on the emptied top
  block). Notion, Docs and Apple Notes all keep the heading with its text. Related: Backspace at
  the start of a non-empty heading or list item at the top of a note does nothing, so a list item
  there has no keyboard route back to a paragraph.
- **Enter at the end of the first line of a soft-broken paragraph gives the new block a leading
  newline** (`afterText` = `"\nbbb"`), which the paragraph model reads back as a separator plus an
  empty row: structure drift from a plain Enter.
- **Backspace-merging into a block with inline formatting lands the caret mid-word**:
  `focusCursorPos` is set to the Markdown length (`**Bold**` is 8) where `placeCaret` counts
  rendered characters (4). Same unit mismatch at `:355`, `:401` and `pasteBlocks.ts:140`; with a
  link above (`[a](url)`, 14 for 1) the caret falls off the end of the block.
- **ArrowDown from an empty block above a divider skips the divider** (a collapsed range in a
  `<br>`-only block has a zero rect, so the last-line test fails), contradicting the rule.
- **Tab at max indent and Shift+Tab at indent 0 commit no-ops** that push undo entries and clear
  `indentStr`: eight Tabs, eight undos, six real steps; a file's tab-indented item loses its raw
  prefix on a Tab that changes nothing.
- The slash menu with no matching command swallows Enter (`preventDefault` before the
  `filtered.length` check), so `/zzz` + Enter neither splits nor closes.

### 1.12 Formatting writes Markdown other readers show literally — correctness, test

- **Bold inside inline code writes literal asterisks into the code**: selecting `foo` inside a
  rendered `` `foobar` `` and pressing Cmd+B stores `` `**foo**bar` `` (the walker handles CODE
  after its children; the renderer processes code first, so the stars appear on the next repaint).
- **Bold across a wikilink edge or a boundary space** produces `se**e **[[Welcome|**Wel**come]]`:
  `**` followed by a space is not left-flanking in CommonMark, so markdown-it and Obsidian show
  the asterisks, while the app's lax regex renders it bold and the user never sees the breakage.
  Plain `a ** word** b` is the same.
- **Copying across list items puts the `●` and `1.` markers into `text/plain` and `text/html`**
  (`cloneContents` includes every marker span after the first block). Every paste into another
  app carries stray glyphs; only the internal `text/boojy-blocks` payload is clean.

### 1.13 Shortcuts that reach the wrong target — correctness, test

- **Cmd+Z, Cmd+Shift+Z and Cmd+Y in any input outside the editor run the note's undo** and
  `preventDefault` the input's own: type in the palette, Cmd+Z, the palette keeps its text and
  the note body behind it loses a word. Same in the sidebar rename input and the title field.
- **Shift+ArrowUp/Down (and Option or Cmd with the arrows) on a block's first or last line
  collapse the selection and jump to the neighbouring block**; keyboard selection across lines
  is impossible from a block's first line and Cmd+Up goes one block instead of to the top.
- **ArrowUp from the first block is a dead key**: it looks for `h1[contenteditable]` but the title
  is a `div[data-title]`, so the title is unreachable from the body by keyboard and the
  `preventDefault` blocks Chromium's own move.
- Cmd+Shift+Z redo matches `e.key === "z"` with Shift; if Chromium reports `"Z"` (the app's own
  `S`/`s` double-check suggests it has been seen), redo is only reachable via Cmd+Y. Playwright
  synthesises `z`, so `undo.spec.ts` cannot settle it; check once in the installed app.
- Typing within 500 ms after Enter or indent shares that history entry (`applyCommit` does not
  reset `historyTimer`), so one Cmd+Z removes the structural change and the text.

### 1.14 Cmd+B, Cmd+I or Cmd+` in a callout body writes `text: ""` until blur — transient, test

`reReadBlockFromDom` on a ref-less block yields `""`; blur heals it, but the formatting is
dropped (`innerText`, see §3.2) and any save inside the window writes an empty callout body.

### 1.15 Dev server only: typing after editing the title drops characters — verification surface, test

The consume-once flags `textOnlyEdit` and `textOnlyEditForEditor` are read inside a `useMemo`
factory and a `memo` comparator. Under `<StrictMode>` (`main.jsx`) React dev double-invokes
both, the second call sees the flag consumed, recomputes `noteTitleSet`, and `EditableBlock`'s
repaint effect paints the per-keystroke sync (one keystroke behind) over the live DOM. Title
`Race`, Enter, type `Hello`: `Helo` or `Hllo` in 12 of 12 dev runs, never in `vite build` +
`vite preview`. It also shows the flag pattern has no margin: a second production reader of
either flag would reproduce it for real users.

## 2. Persistence and the filesystem

### 2.1 External delete while typing resurrects the file and rewrites the vault — data-loss, test

`useFileSystem.js:495-516` rebuilds state from disk via raw `setNoteData` when the watcher
reports a delete. If a text commit is pending (any keystroke in the last 300 ms), `useHistory`
has stopped syncing its ref (`useHistory.js:22`) and then republishes the whole stale ref
(`:207`): the deleted note is back in state, and because every rebuilt object differs by identity,
every note is marked dirty. The deleted note is written to a fresh file (its index entry is
gone) and every other note is rewritten, stamping them all in the recency map. A sync client or
a late `unlink` from a rename's old path is enough to trigger it. Test output: `state after text
flush: ['A','B']`, `written ids: ['A','B']`.

### 2.2 The own-bytes echo hash is never invalidated — data-loss, test

`fileWatcher.js:24` records the bytes of every app write and drops any later event whose file
still holds them, however late. It is never cleared when a *real* outside change is delivered.
Sequence: app writes v1; outside edit to v2 arrives and is adopted; outside change back to v1
(`git checkout`, `git stash pop`, Undo in Obsidian, a Time Machine or sync restore) matches the
recorded hash and is dropped as an echo. The renderer keeps v2 and its next flush writes v2 over
the user's revert. Same on `add`: delete a note, Put Back from the Trash with identical bytes,
and it does not reappear until relaunch. Fix: on a delivered change, replace the entry with the
new file's hash or delete it; delete on `unlink`.

### 2.3 Saving into a folder with a character the sanitiser dislikes moves the file — data-loss, test

`noteToFilePath` (`noteFileManager.js:31`) maps every folder segment through
`sanitizeFilename`. A directory named `Work: Client` or `Draft ` is legal on macOS and comes
from Finder; the first save writes `Work_ Client/Plan.md`, creates that directory, unlinks the
original, and the answer carries only the title, so the renderer keeps `folder: "Work: Client"`
while the file sits elsewhere. Sibling: a pre-existing `Why?.md` is renamed to `Why_.md` on its
first save. Names the app *creates* should be sanitised; names read from disk should only be
validated (the `resolveVaultDir` rule).

### 2.4 Raw `setNoteData` sites are reverted during a text commit and invisible to undo — correctness, test

Same mechanism as 2.1, three more symptoms:

- **Move a note (drag or "Move to"), then Cmd+Z moves the file back.** The move is not a history
  entry (`useSidebarDrag.js:251`, `BoojyNotes.jsx:652`), so undoing the last typing restores a
  snapshot with the old `folder` and `write-note` relocates the `.md`.
- **A drop landing within 300 ms of a keystroke is silently reverted** and the file is written
  at the old location. `useBlockDrag.js:336` is the same shape for block reorders.
- **Undo after a vault switch writes the old vault's note into the new vault.** `changeNotesDir`
  never clears history and `restoreSnapshot` inserts a snapshot whether or not the note exists;
  the dirty scan sees a new id and `write-note` creates the file in the new vault.

### 2.5 Changing the vault never flushes pending edits — data-loss, traced

`changeNotesDir` (`useFileSystem.js:542`) awaits the picker, then `readAllNotes`, then replaces
state, with no flush. The main process saves the new `notesDir` before returning, and `write-note`
resolves the vault live, so a debounce that fires during the read writes the old note into the
new vault; one that fires after finds no note and drops the dirty mark. Fix: flush, then switch.

### 2.6 Typing in a fresh draft and switching note within 300 ms deletes the text — data-loss, traced

Draft promotion waits for the text flush to reach state (`BoojyNotes.jsx:535`); `discardDraft`
runs first on the switch, cancels the pending commit and deletes the draft; the history snapshot
is of the new active note, so Cmd+Z cannot bring it back. Cmd+Q within 300 ms of the first
keystroke in a draft loses it the same way, because `flush` skips `_draft` notes.

### 2.7 A trailing space in the title is deleted under the caret — correctness, test

Type `Meeting `, pause 800 ms: the write lands `Meeting.md`, `useResolvedTitle` sees the field
text equals the written title, repaints the field to `Meeting` with the caret clamped to 7, and
`notes` typed next gives `Meetingnotes`. Any sanitised character mid-typing repaints the same
way; the space is the one nobody sees coming. Fix: while the field is focused, adopt into state
but do not repaint the field, or repaint only when the sanitised text differs by more than
trailing whitespace.

### 2.8 Every save replaces the inode — correctness, test

`atomicWrite.ts` writes a temp file and renames over the target. Proved: mode `0600` becomes
`0644`, `birthtime` resets to the save time, Finder tags and every other xattr are gone. Obsidian
reads `created` from birthtime on macOS; users sort by Finder tags and Date Created; a private
note's permission widening is quiet. The known "symlinked `.md` replaced on write" is the same
root cause. Cheap partial fix: `fstat` the target and `fchmod` the temp file to match; tags and
birthtime need a decision (copy xattrs, or write in place with a backup).

### 2.9 Watcher and index edge cases — correctness

- **External rename or move while edits are pending resurrects the old path** (traced). The
  file-deleted rebuild keeps dirty notes; the flush finds no index entry and `mkdirSync
  recursive` recreates `A.md`, or a whole `Old/` directory, beside the renamed one.
- **A symlinked folder inside the vault is invisible at launch, appears under a phantom folder
  after an outside edit, and vanishes at the next relaunch** (test). The walk uses
  `Dirent.isDirectory()` (false for a symlink); chokidar follows symlinks by default. Pick one.
- **A real external delete landing within 1.5 s of the app's own save of that file is ignored**
  (test). `unlink` (`fileWatcher.js:119`) is the one branch that still decides on the clock alone;
  the app's own writes never produce an `unlink` on the written path, so the check only protects
  the rename's old path, which `suppressNextUnlink` already covers.
- **Blur or quit during a conflict-copy write can put the local version over the outside edit**
  (traced). The dirty mark is dropped before the copy write completes while the id stays in
  `unflushedNotes`; mark `conflicted` before the write, clear on success.

### 2.10 Smaller

- Recency stamping on every text commit rebuilds the sidebar tree (`markEdited` → new `editedAt`
  → `folderTree` recomputed every ~300 ms while typing in recency mode), defeating the text-only
  render bail-out. Stamp only when the note is not already newest.
- Conflict-copy date is UTC (`toISOString().slice(0,10)`); between midnight and 01:00 BST the
  copy is dated yesterday.
- `duplicateNote` drops `content.eol`, so a CRLF note's copy is written LF. `_filePath` reaches
  renderer state from the initial load and the delete rebuild while `onFileChanged` strips it.
- Web only: a quota-failed `localStorage` save falls back to IndexedDB, but the next load prefers
  the stale `localStorage` blob, so the fallback is a decoy. Not product; noted for `dev:web`.
- Attachments whose name contains `#` never render: `main.js:263` builds `"file://" + absPath`
  unencoded, so `photo #3.png` becomes a fragment. `pathToFileURL(absPath).href` in main and
  `encodeURIComponent` per segment in `attachmentUrl.js` fix it (`%` is the known sibling).
- Windows: reserved device names (`nul`, `con`, `aux`, `com1`) are not handled by the sanitiser,
  so such a note fails to save on every flush; `save-image`/`save-attachment` sanitise the stem
  but append the raw extension. Both traced only; no Windows machine here.
- Two legacy files carrying the same `id:` frontmatter hide one of them; falls with the planned
  retirement of the pre-0.5 migrations.

## 3. Blocks and Markdown

### 3.1 Enter or Shift+Enter in a table cell destroys the table on reopen — data-loss, test (two agents)

`TableBlock.jsx:118` intercepts Enter only on the last row; Shift+Enter never. The cell's `<br>`
becomes `\n` through `domNodeToMarkdown`, the row is written across two lines, and on reload the
reader stops at the broken line: the header survives and that row plus every row below it becomes
one paragraph. Other readers see the same broken table. Fix: Enter in a body cell moves down (or
does nothing); Shift+Enter is refused or written as `<br>`; the serialiser must never emit a raw
newline inside a row.

### 3.2 Clicking into a callout body and out strips its inline Markdown — data-loss, test

`CalloutBlock.jsx:269` commits `innerText` on blur. Rendered text has no `**`, `[[ ]]` or
backticks, so `val !== block.text` is true for any formatted body and the stripped text is
committed and written as `> body with bold and Other`. No edit is needed; a click is enough.
`commitTitle` has the same shape. `TableBlock` already uses `domNodeToMarkdown` for exactly this
reason.

### 3.3 Find → Replace changes the file but not the screen — data-loss, test

`FindBar.jsx:161` and `:188` call `commitTextChange` only: no `innerHTML` repaint, no
`syncGeneration` bump (editor gotcha 2). The file changes, the page does not, the match counter
does not move, and the next keystroke in that block writes the old text back. Replace also
targets the nth occurrence in the *Markdown*, not in the visible text, so with `See
[docs](https://docs.example.com) for docs` the second visible `docs` replaces the one inside the
URL. Replace All touches `code` and `frontmatter` blocks and interprets `$&`/`$$` in the
replacement. Find also counts code-block matches twice (the textarea and the overlay).

### 3.4 A pending table-cell edit is lost by any row or column operation — data-loss, test

Cell text only reaches state on blur; the context menu and the drag zones `preventDefault` on
mousedown so the cell keeps focus and never blurs; `insertRow`, delete, drag then reshuffle rows
by index under it (`<tr key={rowIdx}>`), and the typed text is either dropped or committed into
the wrong row. Commit the focused cell before every table operation.

### 3.5 Markdown converters: byte changes on save not in the known list — correctness, test

All run against the real converters; each rewrites a third-party file on its first save or edit.

- **`<https://example.com>` autolinks grow one `;` on every edit** and link to
  `https://example.com>`: `>` is escaped to `&gt;` before the bare-URL regex runs, whose class
  admits `&gt` and stops at `;`. A URL ending in `&` grows the same way. Unbounded byte growth.
- **A link whose text contains a bare URL is scrambled**: `[see https://a.com here](https://b.com)`
  → `[see ](https://b.com)https://a.com here` (autolinking inside an already-built anchor).
- **`[url](url)` collapses to a bare URL** on first edit; Notion exports bookmarks in exactly
  this form, and a bare URL is not a link in strict CommonMark.
- **A soft-broken line that starts with block syntax splits on reload**: `{p "foo\n# bar"}`
  → paragraph + heading; `foo\n- bar` → paragraph + bullet; `foo\n---` → paragraph + divider;
  a soft-broken triple backtick swallows the rest of the note into a code block and the next
  save appends a closing fence. Paste into a heading produces the same shape. This breaks the
  round-trip rule for ordinary Shift+Enter text.
- **Table body rows with trailing whitespace gain a phantom empty cell** (the raw line reaches
  `parseTableRow`; the header row is trimmed and unaffected).
- **An indented callout under a list item** loses its body and its indent: the header is matched
  on the trimmed line, the body consumed with `/^>\s?/` on the raw one.
- **An attachment with no extension comes back as a note embed** (`![[LICENSE]]` → embed).
  **`![[C# notes]]` becomes `![[C#notes]]`**; `![[ Note ]]` is trimmed.
- **Zero-width spaces that belong to the file are deleted on the first edit of their block**
  (the walkers strip every U+200B, not just the caret anchor); `escapes-unicode.md` in the
  preservation corpus promises that byte, and the suite never goes through the DOM so it stays
  green. **Whitespace-only emphasis and code spans vanish** (`a * * b` → `a  b`). **A `↗` typed
  in link text is deleted.**
- **Inline code contents are still formatted**: `` `a*b*c` `` renders italics inside the code
  span and `` `[[x]]` `` is a clickable wikilink inside code. Display only; bytes round-trip.
- **Tags are harvested from code blocks and frontmatter** (`color: #fff`, `#include`).
- Whitespace normalisations: `1.\tfirst` → `1. first`; `>\tquoted` → `> quoted`; `> [!note]
  Title` double space collapsed; UTF-8 BOM dropped when line 1 is a heading or `---`; U+00A0 or
  U+3000 before a list marker removed; ```` ``` js ```` → ```` ```js ````; indented image
  lines dedented.
- `htmlToInlineMarkdown`'s fast path (`inlineFormatting.js:98`) skips the U+200B stripping when
  the input has no `<` or `&`, so a surviving caret anchor can reach state through the Enter-split
  and paste paths.

### 3.6 Rich single-line paste inserts block `<div>`s — correctness, test in real Chromium

`sanitizeNode` (`inlineFormatting.js:251`, `:288`) returns a `<div>` container that its callers
append as if it were a fragment: `<b>bold</b> and <a>link</a>` becomes
`<strong><div>bold</div></strong> and <a><div>link</div></a>`. `insertHTML` renders the divs as
blocks: the line grows to three, the anchor is split, and the walker reads back
`start **bold** and [](https://x.com)[link](https://x.com)end`. Pasting a bold word or a link
from a browser, Word or Docs, or copying formatted text inside the app and pasting it inline,
scrambles the line and writes an empty duplicate link to disk. The unit tests only
`toContain("<strong>")`, so they cannot see the wrapper.

### 3.7 Typing at the start of a block that begins with a wikilink rewrites the alias — correctness, test

`placeCaret(el, 0)` sets the range on `el.firstChild`, which is the wikilink span when the block
starts with one; Home, or arriving by ArrowUp/Down, then typing `X` gives `[[Note|XNote]] after`.
The mirror of the PR #128 fix, which covers only the end of a link. Anchors are safe because
Chromium special-cases `<a>`; spans are not.

### 3.8 Callout type changes never repaint — correctness, test

`editorBlockRenderChanges.ts:29-49` compares only id, type, indent, checked, code text and lang,
table rows and alignments. Picking Warning on a Note callout updates state (type and default
title) and the screen keeps the old icon, title and tint until the next structural edit or note
switch. `handleImageReplace` (`src`, `width`) goes through the same skip and should show the old
image after Replace; not run. `ImageBlock` also never leaves its error state after `src` changes.

### 3.9 Context menus inside the editor column open ~284px right of the pointer — correctness, test

`EditorArea.jsx:517` keeps `transform: translateY(0)` on the column after the fade-in, which
makes it the containing block for every `position: fixed` descendant: the code block's context
menu, the link menu, the image and file menus and the table's create badge all open offset by
the column's left edge and scroll with the page. `TableContextMenu` and the callout picker portal
to `body` and are fine. Drop the transform once the fade has run, or portal the menus.

### 3.10 Block drag ignores non-text blocks — correctness, test

Only `EditableBlock` and `SpacerBlock` register in the block ref map; code, table, callout,
image, file and embed do not. The grip appears on them (it scans DOM children) but pressing it
drags nothing; a drop aimed at the gap just above a code block lands after it; and the insertion
marker is drawn through the middle of the code block, which the UI rule says must never happen.

### 3.11 Table row and column selection keys act on whatever had focus — correctness, test

Clicking a row's left zone tints the row but `preventDefault`s the mousedown, so focus never
moves to the table's outer div; Backspace then edits the paragraph the caret was in. Nothing
ever calls `.focus()` on `outerRef`.

### 3.12 Smaller

- Any two-line paste containing a comma into a table cell is exploded into cells (the CSV
  heuristic is `includes(",") && includes("\n")`).
- A link URL containing `)` is cut at the first `)` (`[^)]+` in the link regex); Wikipedia
  URLs are the common case, and `LinkEditPopover` accepts them unvalidated.
- Escape with the code block's language dropdown open both closes it and leaves the block.
- `TableContextMenu` is not clamped to the viewport (raw `clientX/Y`, no `positionMenu()`).
- `handleBlockNav("prev")` clamps to `textContent.length`, which the rules say never to do.
- Remote images (`![](https://…)`) never load in Electron: `attachmentUrl.js:5` prefixes every
  non-`data:` src with `boojy-att://`. Fine for privacy, but undocumented, and every
  Obsidian or Notion export with hosted images shows broken boxes. Decide and record.
- Dropped files are all treated as images (`useDragDropHandlers.js:80`): a dropped PDF becomes a
  broken `<img>` when `FileBlock` and `saveAttachment` exist for it.

## 4. Sidebar, search, menus, dialogs

### 4.1 Enter in a destructive confirm confirms with Cancel focused — data-loss, live

`ConfirmDialog.jsx:21` focuses Cancel for danger dialogs "for safety"; `:27` registers a
capture-phase window keydown that calls `onConfirm()` on any Enter. Reproduced on web: ··· →
Delete, `activeElement` is Cancel, Enter, note gone (five rows to four). On desktop the same
dialog fronts "Move N notes to the Trash?" and Delete folder. Enter must activate the focused
button. The dialog also refocuses the default button on every app re-render (its effect depends
on `onConfirm`/`onCancel`, fresh arrows each render), so a Tab to the other button is undone by
a toast expiring.

### 4.2 Rename from the ··· or context menu is dead — correctness, live

`useFocusTrap`'s cleanup restores focus to the element that opened the menu after the menu
closes; the rename input has autofocused a frame earlier, blurs, commits the unchanged name and
unmounts. Reproduced: after clicking Rename, zero inputs on the page, focus on the ··· span.
Folders the same. Double-click still works, which is why the harness (double-click only) never
caught it.

### 4.3 The search palette highlights one row and Enter opens another — correctness, test

`_globalIndex` is assigned in group order (root first, folders alphabetically) while the palette
renders and `getActiveResult` reads in score order. With any hit inside a folder the highlight and
the opened note diverge, and arrow keys move the highlight non-monotonically. The unit test
hand-feeds consistent indices, so it passes.

### 4.4 Sidebar drag: hold-to-lift misfires — correctness, test

- A press held 400 ms with 2 px of movement, released on the note's own row, moves a nested note
  to the root: every point in the scroller that is not a folder row or the header resolves to
  "root", including the note's siblings inside its folder.
- A slow click (press, pause, release, no movement) is swallowed: `suppressNextClick` runs even
  though nothing was displaced.
- The drop target goes stale while the list auto-scrolls under a still pointer (traced).

A displacement threshold instead of a hold fixes all three and is what Finder and Notion do;
see the UI section.

### 4.5 The editor's ··· shows the sidebar's bulk menu, and a draft's actions misbehave — correctness, test

With two notes Cmd-selected in the sidebar, the editor's ··· offers "Delete 2 notes / Move to… /
Move to root", acting on the selection rather than the open note. On a draft (the empty state
after deleting the open note), Rename opens no input (there is no row), Duplicate makes a
persisted note titled `" (copy)"`, Delete toasts that "Untitled" moved to the Trash for a file
that never existed.

### 4.6 Smaller

- **Shift-click never selects a range after a plain click**: the anchor is set only by Cmd-click
  and cleared by every plain click. Every list on the platform anchors on the last plain click.
- **Escape closes the overlay sidebar under whatever it was meant to close**
  (`useAppKeyboard.js:78` ignores `defaultPrevented`): at 700 px, Escape on a context menu, in
  the palette or in an inline rename also hides the panel.
- **The palette shows a note's old folder after a move**; the index refresh compares title and
  block count only.
- **Drag-selecting text out of the palette field closes the palette and wipes the query**
  (the scrim's `onClick` is an ancestor of the panel, and Chromium fires click on the common
  ancestor). `ConfirmDialog` has the same shape.
- **Global shortcuts ignore modals**: Cmd+K over Settings opens the palette above it; over a
  confirm dialog, beneath it with two focus traps; Cmd+N and Cmd+Z act on the note behind.
- **Multi-selection is never pruned**: "Delete 3 notes?" after one was deleted outside removes
  two.
- Settings → Storage truncates the path twice (JS keeps the last 30 chars, CSS then ellipsises
  the end of that), so a typical iCloud path loses both its head and the vault's own name.

## 6. Build, tests, security posture

Measured, not read: the gates pass, `pnpm audit` is clean at every level, contextIsolation on,
nodeIntegration off, sandbox on by default, preload exposes fixed channels only, every
path-taking IPC handler goes through the vault guard, `will-navigate` and the window-open handler
deny everything, `open-external` is `http(s)`-only, no source maps or local paths in the asar.
No XSS found: `inlineMarkdownToHtml` escapes before it builds, and the pasted-HTML sanitiser
allowlists tags. What is left:

- **No Content-Security-Policy on the renderer.** The escaping is sound today, but it is a
  hand-rolled regex pipeline across three files and three `dangerouslySetInnerHTML` sites, and a
  CSP (`default-src 'self'; script-src 'self'; img-src 'self' boojy-att: data:; style-src 'self'
  'unsafe-inline'`) is the control that makes a future slip inert. One `<meta>` in `index.html`.
- `javascript:` hrefs survive into the DOM; only the main process filters them. Inert on
  desktop; the web build's `window.open` fallback would follow one.
- The CI audit gate is `--audit-level critical`, so a high does not block; given every dependency
  is dev-only, `high` costs nothing.
- Coverage floors sit 1–2 points under actuals, and `pnpm check` is green with 219 warnings (168
  `useExhaustiveDependencies`), so neither gate can tell drift from signal. Either ratchet and
  silence the deliberate refs-only pattern per file, or accept the noise knowingly.
- GitHub Actions are pinned by major tag, not SHA; `release.yml` has `contents: write`.
- `SettingsModal.test.jsx` asserts its own stub's `isDesktop` logic, not the modal's.
- Zero unit coverage on `useTableInteractions` (710 lines), `useSidebarDrag`, `FindBar`,
  `SidebarContext`, the watcher's event handlers and the `folderOps` object; the Electron suite
  covers their happy paths only. Several findings above (3.1, 3.3, 3.4, 4.2, 4.3, 4.4) live
  exactly there.
- Windows spell-check dictionaries download from Google's CDN on first launch (no
  `setSpellCheckerDictionaryDownloadURL`); worth a line in the privacy statement or a self-hosted
  URL.
- Majors available: Electron 44, Vite 8, Vitest 5, TypeScript 7, jsdom 30. Not urgent; a

## 7. UI thoughts

The framing is the one in the backlog: a lightweight notes app and text editor, Apple Notes
simplicity, files you own, Notion's editing fluidity without its clutter. Nothing below adds a
panel or a feature. It is all about making the small surface behave.

**What is right and should stay.** The chrome is quiet and the decisions behind it read as
deliberate on screen: one tree, the wordmark opening Settings, hover-revealed row controls, the
palette as the only search surface, the slash menu with plain names and typed hints, Dark that
is genuinely dark rather than grey. The paste model (structure only across blocks) and the
gutter grip both feel like an editor with a point of view. The review found no missing feature
that the product needs; it found unfinished edges on features that exist. Fix the edges before
adding blocks.

**1. Finish the three blocks that are half-there before Beta.** Tables, code and callouts each
have a first-class entry in the slash menu and each loses data in ordinary use (§3.1–3.4, §1.3).
A user who reaches for a code block and cannot press Enter at the end, or types into a table and
loses the table, learns not to trust the block, and then the app. The backlog's "Tables:
finished-feeling basic interaction" should widen to the three.

**2. Enter should activate the focused button, everywhere.** The confirm dialog is the sharp
case (§4.1). The pattern to adopt: Enter triggers the focused control; the default button is
the one focused on open; destructive dialogs open with Cancel focused, as they do now, and that
choice then actually protects. No Cmd+Enter special case needed.

**3. Decide Cmd+K.** Two conventions collide: Cmd+K is "link" in Notion, Slack, Docs, Bear, and
"command palette" in VS Code, Linear, Raycast. Recommendation: Cmd+K with a text selection opens
the link popover; with a collapsed caret it opens search; Cmd+P stays as the habit. That keeps
both muscle memories and needs no new shortcut. The alternative (link on Cmd+Shift+K) is
learnable but nobody types it. Either way the popover should never open on a collapsed caret at
the editor origin.

**4. Menus should complete only what the user chose.** The tag menu capturing Enter and Space
(§1.2) is the same design pressure that produced the wikilink rule ("menus own their keys").
The rule is right for a menu the user has navigated; it is wrong for a menu that merely popped up
under a word being typed. Proposed grammar for tag, wikilink and slash alike: Space and
punctuation always pass through; Enter completes only if the user has arrowed, or if the
highlighted suggestion differs from what is typed; otherwise Enter does what Enter does. Tab
could be the explicit "take the suggestion" key, as in every IDE.

**5. Replace hold-to-drag with a displacement threshold.** The 400 ms hold (§4.4, and the known
backlog item) is the cause of three misbehaviours and the reason the hint is needed at all.
Finder, Notion and Obsidian all lift a row after ~5 px of movement with the button down and never
on a timer. That removes the slow-click swallow, the twitch-to-root, and the discoverability
problem in one change. The note's own row and its siblings should read as "no move", not "root".

**6. Slash menu placement.** Two small things. First, put the caret inside code, callout and
table when they are chosen (§1.5); the paragraph-after is right only for divider and image.
Second, consider opening `/` after a space mid-line as well as at the start of an empty block.
The typed hints made the menu the discoverable path to every block; a menu that only opens on an
empty line teaches people to press Enter first, which is the ceremony the product is trying to
avoid. If mid-line is felt to be noisy, the compromise is "start of an empty block, or after a
space", which is what Craft does.

**7. Undo should feel the same in every block.** Per-character undo in code (§1.4) and blur-only
commits in tables and callouts are three different undo grains in one note. One rule: text
commits coalesce over the same debounce everywhere, structure commits are one entry each. That
also makes the gutter grip's "one history entry per drop" promise hold for non-text blocks once
they can be dragged (§3.10).

**8. Toasts and the empty state need ink.** A toast on Dark that cannot be read (§5) is worse
than no toast, and "Failed to save" is the one message that must land. `ACCENT.onAccent` on the
info toast, dark ink on the warning toast, and the empty-state line at full `TEXT.muted` rather
than half of it. The focus ring at 25% accent is under 2:1 on both themes; 3:1 is the floor for a
component, and a 2px ring at 60% would still be quiet.

**9. Search results: one separator.** The body snippet concatenates blocks with a single space
(`…#tagonehere. first item..`), so a heading and the line under it read as one sentence. A
middle dot or a thin `·` between blocks is enough. And the palette should agree with itself
about which row Enter opens (§4.3).

**10. Small courtesies.** Rename from a menu should work (§4.2); the editor ··· should always be
about the open note (§4.5); Shift-click should range from the last plain click (§4.6); Escape
should close one layer at a time; the Storage path should show the vault's own name. None of
these is a feature. Each is a moment where the app currently contradicts the platform, and a
lightweight app earns trust precisely by never doing that.

**Deliberately not proposed.** Visible undo buttons, a "+" beside the grip, a block menu on the
grip, a source view toggle in the chrome, tabs, a recent list in the empty palette, per-note
icons. The backlog already has the right answer on each, and nothing in this review argues for
reopening them.
