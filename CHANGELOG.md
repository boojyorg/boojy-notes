# Changelog

## Unreleased

### Improvements

- **Right-click on text gives you Cut, Copy and Paste** — Right-clicking in a note used to do nothing at all unless the pointer was on a link, so there was no way to cut, copy or paste without the keyboard. It now opens a menu with Cut, Copy and Paste, each with its shortcut shown beside it; Right-clicking a word you had not selected selects it first, as on any Mac, and the menu opens just below the selected words, lined up with their left edge, and the words stay selected in the usual blue while it is open; Cut and Copy are greyed out when nothing is selected. Right-clicking a link shows its own actions (Open, Copy, Edit link…, Remove link) with Cut, Copy and Paste underneath, in a menu that now matches the rest of the app's, with icons and arrow-key support. The formatting bar steps aside while the menu is open. Pictures, files, code blocks and tables keep their own menus.
- **Menus have rounded rows, like the sidebar** — The highlighted row in the `/` menu ran square from one edge of the menu to the other, and the other menus used a tight, nearly square corner. Every menu now draws its highlighted row as a rounded pill set in from the edges, the same shape as a note you point at in the sidebar, with slightly rounder menu corners to match: the `/` menu, right-click menus, Sort, the tag suggestions, a code block's language list, the table, image and callout menus, the link picker and the folder popup.
- **Images have a quieter set of controls, and a click no longer opens them full screen** — An image used to grow a light teal border when you pointed at it, and a single click both selected it and opened it full screen, so there was no way to select a picture to delete it without the full-size view getting in the way first. Now a picture shows nothing extra until you point at it. Then a small bar appears at its top right, with a button to see it full size and a ··· for its menu, and a thin white handle appears on its right edge. Drag the handle to make the picture narrower or wider. It clicks into place at the picture's original size. That width is saved in the note, the same way Obsidian stores it, and going back to the original size removes it again; double-clicking the handle does that too. The bar and handle show only while the pointer is on the picture, and the handle looks the same whether you are pointing at it or dragging it. A click now just selects the picture, the moment you press rather than when you let go, and it gets a faint teal tint, so Backspace deletes it (a divider now selects on the press too); clicking anywhere else, even just beside the picture, in the margins or in the sidebar, lets it go again. A double-click, or the button in the bar, opens it full size, now with its file name at the top and a close button. While you drag, the handle stays at the height you grabbed it instead of sliding up or down as the picture's height changes. Right-click and the ··· open the same tidied-up menu: View full size, Copy image, Show in Finder, Original size (when you have set a width) and Delete. Replace image is gone: delete the picture and drop the new one in. Using the menu no longer leaves the picture selected, and no longer makes the note jump: closing any menu or dialog used to scroll the note to wherever your text cursor was.
- **Images come in at a sensible size** — Every image used to fill the full width of the note, whatever its size: a small icon was stretched until it blurred, and a screenshot came out bigger than it looked on your screen, because a Retina Mac saves twice the pixels it shows. An image is now drawn at its own size and never enlarged, so small pictures stay small and big ones still stop at the edge of the note. A screenshot you add is drawn at the size it was on screen, and that width is saved in the note (`![[Screenshot….png|524]]`) so Obsidian shows it the same size. A width already in a note is now read as pixels, as Obsidian reads it, so an image sized in Obsidian looks the same here; one you resized in Boojy Notes before this may come out a little smaller than it was. Images already in your notes are never rewritten just by opening them, and dragging an image's corner still sizes it by hand.

### Bug Fixes

- **Links whose address has brackets in it go to the right page** — A link like `[Mercury](https://en.wikipedia.org/wiki/Mercury_(planet))`, which is how Wikipedia names half its pages, was cut short at the first `)`: the click opened `…Mercury_(planet` and a stray `)` was drawn after the link. The same happened to a bare address pasted into a note. An address now keeps brackets that open and close inside it, while a `)` that closes your own sentence, as in `(see https://example.com)`, still stays outside the link. The file was never changed; only the display and the click were wrong. An image whose file name has brackets in it (`Screenshot (2).png`, written as a Markdown image) is now shown as the image rather than as a line of text.
- **Images can be dragged into a note from anywhere on the page** — Dragging a picture in from Finder or the desktop only worked if you let go exactly over a line of text; under a short note, in the margins or near the top, the pointer showed a "no" sign and the release did nothing, which felt like dragging images in was not supported at all. The whole page takes the drop now. While you hold the file over it, a thin teal line shows the gap it will land in, the same line that shows where a dragged block will go: over the top half of a paragraph it goes above it, anywhere below the last line it goes at the end.
- **Several images at once all arrive, in order** — Pasting several image files at once kept only the first and silently dropped the rest, and dropping several could put them in a different order from the one you picked them in. Both now add every file, one under the other, in the order given.
- **Images with a space in their name show up** — An image whose file name held a space, which is every macOS screenshot (`Screenshot 2026-09-23 at 10.12.33.png`), drew a dashed "Image not found" box instead of the picture, while a pasted image, named `paste-…` by the app, loaded fine. The file was saved and the note was right; only the display failed, so an Obsidian note with such an image failed the same way. Names with spaces, square brackets, a `%` or accented letters all load now. And a broken image that you replace now shows the new picture rather than keeping its "Image not found" box.

## v0.9.0 — 2026-09-20

### Improvements

- **Search opens on your recent notes** — Press ⌘P with nothing typed and the palette now lists the notes you opened most recently, newest first, with the note you are in left out, so ⌘P then Enter takes you back to where you just were. Up to eight are shown, fewer in a short window, and the list survives a restart. Opening a note this way never moves it in the sidebar's "Most recent" order, which still means most recently *edited*. The first character you type replaces the list with results; clearing the field brings it back.
- **Search results say why they matched** — A note found by its name is one line, the matching letters in teal, its folder muted on the right. A note found only by what is in it carries one short muted excerpt under its name with the matched words in teal, and a `·` where the excerpt crosses from one paragraph into the next. Several words find a note that has all of them anywhere, in any order; a name starting with a word ranks above a name merely containing it; `cafe` finds `Café`; the initials of a name work too (`tn` finds Todd's Note). Pressing Enter the instant you finish typing opens the note you were typing towards, never a result from the keystroke before. Opening a result found in the body scrolls to that passage.
- **Tags are pills, and a tag click filters Search to exactly that tag** — A `#tag` in a note is drawn as a small rounded pill, teal on a faint teal ground, from the first letter you type after the `#`, and stays plain `#tag` in the file. Click one and Search opens with the tag as a removable chip in the field, every note carrying exactly that tag listed at once, and the field ready: typing then searches only inside those notes. Typing `#` in Search lists your tags as rows, most used first, and Enter or Tab on one sets the same chip. Backspace on the empty field puts the tag back as text to edit; the chip's × drops it; Escape closes in one press either way. A tag is one tag whatever its capitals (`#Work` and `#work`), and `#café` is not `#cafe`.
- **The sidebar stays put behind Search** — Typing in the palette used to filter the sidebar tree under the dim, hiding folders and notes whose names did not match and collapsing an empty result to nothing. The tree now stays exactly as you left it, sort and open folders included; results live in the palette alone.

- **One Link for web addresses and notes** — Cmd+K, the Link button in the selection toolbar and typing `[[` now open the same small picker: `Paste a link or search notes…`. Type an address, with or without `https://`, and the first row is `Link to youtube.com`; type a name and the notes that match are listed with their folder beside them, so two notes called Goals are told apart; a name no note has ends the list with `Create note`, which makes the note next to the one you are in and links to it without leaving. With words selected, they become the link's text: `[[Goals|my plans]]` for a note, `[my plans](https://…)` for an address. With nothing selected, a note link shows the note's name and an address shows as itself. Typing `[[` still offers only notes. Editing a link (Cmd+K with the caret in it, or right-click, Edit link…) shows Text and Destination separately, so a pasted YouTube address can read "Link to YouTube" without touching where it goes; Enter or clicking away applies, Escape cancels, and a destination that is neither a note nor an address is refused rather than written. Remove link keeps the words. Resting on a link for a moment, or moving the caret into it with the arrow keys, shows a small chip with where it goes: the address, or the note's name and folder.
- **A link that could mean two notes, or none, asks instead of guessing** — Two notes with the same name used to resolve to whichever loaded first, and a link to a note that did not exist created one at the top level the moment it was clicked. Both now draw as unresolved with a dashed underline, the chip says why (`2 notes share this name`, `no note by this name`), and a click opens the picker with the candidates, or `Create note`, as its rows. Nothing is opened, made or rewritten until you choose. Renaming or moving a note still leaves links to it in other notes as they were; the picker is the way to point them at the new place.
- **Move to… — a note or folder can be moved without dragging it** — Right-click a note or a folder, or open the ··· menu at the top of the note, and there is now a Move to… item beside Rename and Duplicate. It opens a small tree of your folders under the menu, with Notes at the top for the root and a tick beside the folder the thing is in now. Click a folder to move it there; the small arrow at a folder's right edge opens it to show the folders inside, so opening never moves anything by accident, and the arrow keys and Enter do the same. A folder you are moving is greyed out in the list, along with everything inside it, because a folder cannot go into itself. With the sidebar hidden, the ··· menu at the top of the note is the one place this lives, which was the point: until now there was no way to move the note you were looking at without opening the sidebar to drag it. The same Move to… replaces the old flat list in the menu for a multi-selection, and with notes chosen from several folders nothing is ticked. Moving keeps everything: the note stays open, unsaved typing goes with it, and the path at the top of the note redraws. If the sidebar is open, the folder it landed in opens and the moved row is lit for a couple of seconds so you can see where it went; a hidden sidebar stays hidden.
- **Notes and folders can be dragged inside the folder popup at the top of the note** — Click a folder in the path above the note and the small tree that opens now lets you press and hold a note or folder and drop it onto another folder in that tree, exactly as the sidebar does, with the same lifted pill and the same highlighted target. The tree now starts with the folder it is showing (Notes for the top level), so dropping a note on that first row moves it up and out of the folder it is in. A release anywhere but a folder row flies it back and moves nothing, and so does Escape. A plain click still just opens the note or folder as before.

- **An empty heading says which heading it is** — Type `# ` or pick a heading from the `/` menu and, until you write something, the empty line shows a faint "Heading 1", "Heading 2" and so on in the heading's own size, exactly as Notion does. The first character replaces it, and deleting back to nothing brings it back. It is drawn by the editor rather than written into the line, so it never ends up in the file or in anything you copy.
- **The top of both columns sits a touch lower** — New note and the note's first line have moved down a few pixels together, with Notes tucked a little closer under New note, and the note's first line now sits two pixels under New note's baseline rather than exactly on it: level, a small label beside a big heading read as sitting high.
- **A duplicated folder shows you where it went** — Duplicating a folder made the copy silently: it appeared in alphabetical order beside the original, which could be anywhere in the tree, including out of sight. The tree now scrolls the copy into view and its row is lit for a couple of seconds, so you can see what was made and where it landed, rather than being told about it in a message. Duplicating a note is unchanged — it opens the copy, which is its own answer.
- **Interface size is in Settings, and the shortcut says what it did** — How big the app draws everything could only be changed with `⌘+` and `⌘−`, which meant nothing in the app said the feature was there, nothing said what size you were on, and nothing said `⌘0` was the way back. Settings → Appearance now has an Interface size row: − and + either side of the figure in one small control, and every press takes effect immediately. **Settings itself stays exactly where it is while you use it** — the app behind the panel resizes under each press, the panel does not, so the button stays under your pointer; close and open it again and the panel is drawn at the new size. Clicking the figure lets you type any whole percentage in the same range, applied when you press Enter or leave the field and never while you are typing it; Escape cancels, and so does anything else that changes the size first, so a half-typed number can never land on top of it. Reset appears whenever you are off 100%, and nowhere else — at 100% there is nothing to go back to. The shortcuts keep working, including while Settings is open (the one shortcut that does), and outside Settings they answer with a small chip at the foot of the note: `Interface size 120%`, carrying `⌘0 resets` while there is something to reset. Pressing the shortcut at the smallest or largest size answers with the size you are on rather than doing nothing, and from a typed size `⌘+` and `⌘−` move to the nearest size in the list. The sizes themselves are unchanged.
- **The note's first line starts level with New note** — The first line of a note and the New note button in the sidebar sat on slightly different lines, and how far out they were depended on what the note opened with: a heading was about ten pixels lower than the button, a paragraph half a pixel. Near enough to look like a mistake rather than a decision. They now share a baseline, the line the letters sit on, whatever block opens the note. A heading does that by reaching upward from the line rather than pushing it down, so the first line you read is in the same place in every note, and it does not move when you turn that first line into a heading by typing `# `. The space between every block below the first is exactly as it was.
- **Every shortcut works the same way now: type the marker, press space** — `# `, `- `, `1. `, `> ` and `[] ` have always waited for a space before becoming a heading, a bullet or a to-do. `---` and `|||` did not: they turned into a divider and a table the instant you finished typing them, which meant you could never type a longer run of either, and never say anything more about what you wanted. Both now wait, and Enter does the same thing as the space. `--- ` makes a divider as before, and so does any longer run: `----------` is the same rule, since three dashes or more is what a rule *is* in Markdown. The table gains something real from the wait — **the pipes are the row you are drawing**, so `||| ` is the two-column grid it always was, `|||| ` gives three columns, `||||| ` four, up to eight. A run of pipes is ordinary text until the space, so you can type `|||` in a sentence at last.
- **A code block can be typed with its language: ` ```js ` and a space** — Three backticks used to turn into a code block the instant you finished typing them, which made it the one shortcut in the editor you could never finish: typing ` ```js ` gave you an empty block with a stray `js` in it. A fence now waits for a space, exactly as `# `, `- ` and `> ` do, and whatever you typed between the backticks and the space is the language: ` ``` ` opens a plain block, ` ```js ` a JavaScript one, ` ```py ` Python. Enter works too, so ` ```py ` then Enter is the same thing. A language the app does not highlight, `rust` or `yaml`, still opens a block and keeps its word. And because the space is what converts, three backticks are three backticks until you ask for the block, so a literal ``` can be typed at last. What you typed is what the file says: ` ```js ` stays `js` on disk, the way Obsidian leaves a fence exactly as you wrote it, while the corner of the block reads `JavaScript`. Existing notes gain that too — a file that says ` ```py ` used to read `py` in the corner with nothing ticked in the language menu, and now reads `Python` with Python ticked.
- **The code block's language list is the same menu as everything else** — Clicking the language at the bottom right of a code block used to drop a list of its own making: smaller, greyer text than the app's other menus, a typed `✓` in front of the chosen one, no keyboard at all, and it opened upward over the code you were looking at. It is now the menu the sidebar's Sort control uses, opening under the label with the chosen language ticked in the app's teal. Arrow keys move, Enter chooses, Escape closes, and typing a letter jumps to a language, so `t` then Enter is TypeScript. The order is Plain, then alphabetical, rather than a running order of how often each is used. The label itself now shows a small chevron when you point at it, which is the only thing that ever said it was a control. Right-clicking a block still offers Change language, and it opens the same menu rather than a second copy of the list in a submenu; that menu's three items read as sentences now (`Copy code`, `Change language`, `Delete block`).

### Bug Fixes

- **Search no longer lights up unrelated words** — Searching `todd` marked "Today I de" in a note that never mentioned Todd, because the search accepted any note containing the letters t‑o‑d‑d in order, however far apart, and highlighted everything between the first and the last. Scattered-letter matching is gone; a result contains the words you typed.
- **Search sees what you just typed** — The search index refreshed a note only when its name or its number of paragraphs changed, so text edited inside a paragraph was invisible to Search until something structural happened. It refreshes on every edit now, and the tag list follows the text as well.
- **A tag search is exact, and code is never a tag** — Clicking `#work` used to run a text search for `#work`, which also listed every note with `#workshop`; it now lists the notes tagged `#work` and no other. `#include` in a code block, `color: #fff`, `a#b` and the `#section` of a web address are no longer offered as tags, while searching for them as text still finds them. Tag names may include accented letters.

- **The toolbar's Link button works** — Clicking Link in the selection toolbar did nothing; only Cmd+K opened the link field. The click was opening the field and, in the same instant, counting as a click outside it. It opens now, with the field ready to paste into.
- **Inline code has a shortcut that works on every keyboard: Cmd+E** — The toolbar chip said Cmd+` for inline code, and on a Spanish keyboard (and most European ones) that key is an accent key, so the shortcut never fired. Cmd+E, the same key Notion uses, now does it and is what the chip shows. Cmd+` still works on keyboards where the backtick is a plain key.
- **The block handle no longer vanishes for the rest of a note** — Two ways the grip in the left margin could disappear until you switched notes are gone. Pressing any key while the pointer rested on the grip (Cmd+Z, typically) hid it and it never came back for that note; and pressing the grip then switching apps with Cmd-Tab left the press half-made, so the next mouse movement started a ghost drag with no button held, the grip went missing everywhere, text stopped selecting, and the next click dropped a block somewhere. Both now clean up after themselves.
- **One Cmd+Z no longer takes back two things** — Typing, pressing Enter (or pasting, or ticking a box), and typing again without a pause was one undo step: the text after the Enter was folded into it. Each is its own step now.
- **Redo works inside a code block** — Shift+Cmd+Z in a code block did nothing; the block was stopping it before the app could see it. Cmd+Z and Ctrl+Y were fine.
- **Undo while renaming keeps your place** — Cmd+Z with the caret in the note's name threw the caret to the start of the name. It stays where it was.
- **A note always opens at its top** — Scroll down in one note, open another, and the new note could start scrolled: its first line sat up under the path row instead of level with New note in the sidebar. This is one of the two reasons those two could look misaligned; the other is an interface size other than 100%, where the two columns round to different pixels, which is not changed here.
- **Triple-click selects a list item** — Triple-clicking a line is meant to select all of it, and in a paragraph it did. In a numbered list or a to-do list it selected nothing at all, and a bullet only did when another bullet followed it. The browser stretches a triple-click to the start of the next line, and when that line begins with a number or a checkbox it gives up and drops the whole selection. The editor now selects the line you clicked itself, and the selection stops at the end of that line rather than reaching into the one below.
- **Settings stays on screen at every interface size** — At 200% the Settings pane was sized to twice the window, so its title and close button sat above the top edge with no way to reach them: the sizes it is built from ignore the app's own scaling. Settings and the first-run welcome now measure themselves against the window as you actually see it, at any size.
- **Notifications are quiet, and the ones that matter stay put** — The little message at the bottom of the window after deleting a note was a wide teal slab with white writing on it, which was both the loudest thing on screen and, at that contrast, the hardest to read. Every notification is now the same quiet surface the menus use, with one small coloured mark to say what it is: grey for something that went well, teal for something worth knowing, amber and red for a warning and a failure. It sits at the foot of the note rather than the foot of the window, so it never covers the sidebar row you just changed, and it slides across with the sidebar. What it says now decides how long it stays: a note moved to the Trash is a receipt and fades after a moment, while a failed save, a warning or the notice that your edits were kept in a conflicted copy waits with a × until you dismiss it. A failed save no longer piles up one message per retry either — it is one message, and when the save does go through it is replaced by a short "Saved" that fades, so you are never left reading a warning about something that has since worked.
- **The second resize of an image no longer snaps it back** — Dragging an image's corner worked once. Drag it again and the image jumped back to the size it was before the first drag, then followed your pointer from there. The file was always right, and so was the note after you reopened it, which is what made it feel so odd. The same cause quietly broke Replace image: picking a new picture changed nothing on screen until you happened to edit something else in the note. Both are fixed, and a resize now continues from where you left it.
- **A press on the edge of a checkbox ticks it** — Press a to-do's box near its edge, hold for a beat, and you would see the little squeeze animation and then nothing: the task stayed unticked. The box shrinks while it is held, which moved it out from under the pointer, so the release landed on the line rather than on the box. The squeeze is now drawn on top of a target that does not move, so the press counts wherever on the box it started. The box itself is exactly where it was, and the target is still the square you can see rather than a generous area around it.
- **A code block can be dragged by its handle** — The grip in the left margin appeared beside a code block, a callout and an embed, and pressing it did nothing at all. For a code block that meant there was no way to move it: the keyboard shortcut needs the caret, and a code block keeps every key you press inside it. Nothing could be dropped above the first code block in a note either, since the space above it was not a place the drag could see. All three move now, by the grip or by dropping another block above them.
- **The handle sits on a code block's first line, blank or not** — It looks for the first line of a block by finding its first letters, which is right for prose and wrong for code, where an empty line is still a line. A code block that opened with a blank line put the grip two rows down, beside the first line with something on it, and an empty block put it somewhere of its own. It now asks the block which row is its first.
- **Arrow keys around a code block behave** — Four things, all of them daily annoyances. Leaving a code block, a callout or a table cell with the arrow keys put the caret in the right place but **threw the page back to the top of the note**, so you lost your place every time you stepped out of a block. The arrow keys **stepped straight over a code block** in both directions: coming down from the paragraph above you landed in the paragraph below, and the only way into a block was to click it. A key pressed inside a code block could reach the editor around it and act on wherever the caret used to be, taking focus out of the block or, at worst, typing your character into the top of the note. And in an empty paragraph, ArrowDown did nothing at all, so a divider or a table under a blank row could not be reached from the keyboard. The arrows now walk into a code block at its first line coming down and its last line coming up, exactly as they have always walked into a table, and the note stays where you left it. Backspace is unchanged: it still steps over a code block rather than merging text into it.
- **Typing ``` puts the caret inside the code block** — It used to make the block and leave the caret in the paragraph below it, so the first line you typed landed as ordinary text underneath an empty code block, and you had to click into the block to start. The caret now goes into the block, exactly as it does when you make one from the `/` menu.
- **The formatting strip stays whole at the edge of the column** — Select the first word of a line and the little bar of B, I, S and the rest is centred over it, which put half of it past the left edge of the note, where it was cut off rather than shown: in a narrow window the B could be missing altogether. It now steps in far enough to stay whole, sitting as near the centre of your selection as it can, and it does the same at the right edge; in a column narrower than the bar itself, it centres. It also sits where it should when the interface is scaled: at anything but 100% its position was scaled a second time, so it drifted further from the selection the further down the note you were.
- **Bold and Italic light up with the press** — Pressing B or I in the formatting strip formatted the text at once, but the button itself only turned teal about a third of a second later, waiting on the note's next save, so the strip read as sluggish even though the word was already bold. The button now changes with the press, and its colour no longer fades in over it.
- **Bold and italic work inside a table and a callout** — Selecting a word in a table cell brought up the formatting strip, and pressing anything on it did nothing at all: not the word, not the file, no message. The keyboard was worse than useless. In a body cell the browser happened to bold the word behind the app's back, so it worked by accident; in a header cell, where the text is already half-bold, `Cmd+B` quietly *unbolded* it into something the file never recorded, so the word went lighter on screen and the note on disk never changed. Formatting now works in a table cell and in a callout's body exactly as it does in a paragraph, by the strip or by the shortcut, and what you get is ordinary Markdown in the file: `**bold**`, `*italic*`, `` `code` ``, `~~strikethrough~~`, `==highlight==`. The strip in a cell shows five buttons rather than six, because links inside a cell are not ready yet and a button that cannot do anything is worse than no button. A callout's title and the inside of a code block hold plain text and cannot carry a format, so the strip no longer appears over either of them, nor over a selection that runs from one cell into the next.

## v0.8.0 — 2026-09-17

### Improvements

- **Enter in a quote stays in the quote** — Pressing Enter inside a quote used to start a second quote under it, with its own bar and a gap between, which is not what the file said: two quotes written one under the other are one quote to every Markdown reader, so reopening the note joined them back into a single bar. Enter now moves to a new line inside the same quote, as it does in Obsidian and Notion, and Shift+Enter does the same. To leave the quote, press Enter on an empty line at its end and you are in a paragraph below it, exactly as an empty bullet becomes a paragraph. Quotes are also no longer italic: the bar on the left is the mark, the text reads in the ordinary ink, and a word you italicise inside a quote now shows as italic, which it could not while everything around it already was.
- **A paragraph break is a little tighter** — The space Enter puts after a paragraph or quote is 8px rather than 12, so a new paragraph reads as the next line with a breath before it rather than a gap. Shift+Enter is still a plain line and an empty line is still a whole row; the file is unchanged either way.
- **Settings looks like the rest of the app** — It used to be its own thing: uppercase teal section labels with a teal rule beside them, a teal-filled theme picker, grey chip buttons, a heavy blurred backdrop and a `✕` typed as text. It is now one pane on the same surface as Search: a cog beside the title, three sections parted by hairlines, section titles in the quiet grey the sidebar's `Notes` label uses. Appearance is three pills, Light, Dark and System, each with its glyph, the chosen one on the ordinary grey. The notes folder is written out in full and wraps at its folders rather than being cut short, and the folder glyph and path are one control: rest on it and it says Show in Finder, click and the folder opens. `Change folder…` sits beside the path, or under a long one, and first asks `Change notes folder?` with the one thing worth knowing: your current notes stay where they are. Updates is the `Automatic updates` switch, one line of status and one button that says what it is doing, `Check for updates`, `Checking…`, `Downloading…`, and `Restart to update` when there is something to install; a failed check says so and offers `Try again`. The footer reads `Boojy Notes v0.7.0 · boojy.org/notes`. In Dark, enabled buttons now have a surface of their own so they no longer look disabled, and a label on the teal is dark ink rather than white, which was hard to read on it.

### Bug Fixes

- **Updates can now install on macOS** — Settings → Updates could find a newer version but never install it: the release carried only a DMG, and the updater installs a macOS update from a zip, so the download failed the moment one was found and Settings showed `Try again`. Every release now publishes the zip beside the DMG. The DMG is still what boojy.org offers; the zip is what a running app fetches. This is the first release the installed app can update itself to, so v0.7.0 is the first version that updates in place.
- **Typing a name that another note already has no longer gets `-2` stuck on mid-word** — Writing `Tyres` in the name field, with a note called `Tyr` beside it, turned into `Tyr-2` the moment you paused after `Tyr`, and carried on from there. The app saves as you type and the file did need a different name for that instant, but the name in the field is yours until you press Enter or click away: it now keeps exactly what you typed, and only takes the file's real name (`Tyr-2` if you really did stop at `Tyr`, or a version with characters a filename cannot hold replaced) once you leave the field.
- **Backspace in an empty note no longer breaks the editor** — In a note with nothing in it, a new one or one you had just emptied, pressing Backspace made the `Type / for commands...` hint vanish, and everything typed after it went nowhere until you opened another note and came back. Chromium was deleting the note's only line itself. The key now does nothing there, as it should.
- **The sidebar's panel toggle is never cut off at the narrowest width** — Drag the sidebar to its minimum and the toggle in its top row lost most of itself past the divider: the row holds the traffic-light gap, the wordmark, Search and the toggle, and those add up to more than the 200px the sidebar could shrink to. The minimum is now worked out from what the row holds, so every control in it stays whole, and the window's own minimum width follows it (545px, from 520). The wordmark also sits four pixels nearer the traffic lights.
- **Renaming in the sidebar no longer draws a box** — Renaming a note or a folder put a bordered field over the row: the name jumped a few pixels right, the folder's name shrank to a smaller size, and the row's hover pill and its glyphs stayed lit behind the box. The name now stays exactly where it is and is simply selected, ready to type over, with the pill and the trailing glyphs gone until you finish. A folder's name is now selected in full too, as a note's already was; before, the cursor sat at the end and typing appended. A folder is renamed from its ··· menu only: double-clicking one used to open and close it under the field, so now every click on a folder just opens or closes it. Notes still rename on double-click.
- **A menu opens with nothing highlighted** — Open a note's, a folder's or the top-right ··· menu and one item, usually Rename, could already be lit before the pointer reached it. The menu remembered whichever item you last hovered in the previous one. Every menu now opens clean, and moving the pointer off an item unlights it.
- **Menu items no longer carry a dark line over each row** — The note-row and top-right menus mixed a border shorthand with a top-border longhand in one style, and React cleared the edge the shorthand had just set, so Chromium's own button border came back as a dark rounded line over every item without a separator. Each box edge is now set once.
- **A row's ··· menu near the bottom of the window no longer opens over the row** — When there was no room below, the menu flipped up to end exactly at the row's bottom edge, covering the row, and because the pointer was still on the dots it landed inside the menu's last item, Delete, which lit up the moment the menu opened. The menu now sits above the row instead, with nothing highlighted until you move.
- **Images and file attachments can be dragged by the grip** — Hovering an image showed the six-dot grip in the margin like any other block, but pressing it and moving did nothing: the note stayed put and nothing followed the pointer. The grip now lifts an image or a file attachment exactly as it lifts a paragraph, with the same translucent copy, the same insertion line and one Undo step on release. Dragging another block past an image also lands where the line says: the image used to be invisible to the drop, so a release over its top half put the block under it. Keyboard reorder (Cmd+Shift+Up/Down) already moved images and is unchanged.

- **Copied blocks keep their headings and lists in other apps** — Selecting a heading, two lines and a bullet and pasting them into Obsidian gave five plain lines: the `#` and the `-` were stripped from the plain text on the way out, and the formatted version flattened every block to a line break. A copy that takes whole blocks now puts their Markdown on the clipboard as plain text, exactly as the note's file would spell them, and their structure as real headings, lists, quotes, code and tables for apps that take formatted text, so Obsidian shows the same note and Notes or Mail show headings and bullets. Selecting words inside a line still copies just those words, as before, with their bold or italic carried in the formatted version and no Markdown symbols added to the plain one. The small ↗ beside a link no longer travels with it, and a `[[wikilink]]` is written as such rather than reduced to its word. Pasting back into Boojy Notes is unchanged. Images and attachments copy as their `![[…]]` reference, not the file.
- **Bold in a heading makes the word bolder, not lighter** — Selecting a word in a heading and pressing Cmd+B, or the toolbar's Bold, made it *thinner*: the browser's own bold command looked at the heading, saw text that was already bold, and took the press as "remove bold", and the file never got the `**` either, so the word snapped back on the next repaint. Bold and italic on a selection are now applied the way strike and highlight already were, wrapping the words themselves, so a bold word in a heading is written as `## Release **day**` and drawn one step heavier than the heading around it. Italic inside a quote had the same fault in the file and is fixed by the same change. Pressing Cmd+B with nothing selected, to type in bold from the caret, is unchanged.
- **Clicking a link Obsidian wrote no longer creates a stray file** — A link to a heading, a block or a note in a folder, `[[Beta#Intro]]`, `[[Beta#^ref]]` or `[[Work/Gamma]]`, is what Obsidian writes for those three cases, and Boojy Notes could not read any of them: a click looked for a note called `Beta#Intro`, found none, and made one, so the vault gained `Beta#Intro.md` or `Work_Gamma.md` (names Obsidian itself refuses) and the link still went nowhere. A click now opens the note the link names, Beta, or the Gamma inside Work (a path in a link means that path, never a note of the same name somewhere else), and the link is no longer drawn as broken; jumping to the heading or block is still to come. Clicking a plain `[[Delta]]` with no such note still creates Delta, as before. A heading, block or folder-path link to a note that does not exist creates nothing: a small message says which note is missing, the link stays exactly as written, and nothing is added to the vault. The right-click menu on such a link offers Open Note rather than Create Note. Proven in the real-Electron suite: what opens, and every file in the vault before and after each click.
- **A note's properties stay at the top of the file** — In a note with YAML frontmatter (the properties block Obsidian writes between two `---` lines), pressing Cmd+Shift+Up on the first block under it moved that block above the properties, and the file was saved with the `---` no longer on its first line. To Obsidian, and to Boojy Notes on the next open, that is no longer frontmatter: the properties turned into a heading, a rule and a few lines of text, and the note lost its tags and aliases. The same happened when the first thing under the properties was the blank line Obsidian leaves there, which then went to the top of the file as an empty line. The properties block is now the head of the file and not a block in the body: nothing can be moved above it by keyboard or by dragging (the drop marker's highest position is the gap under it), and it shows no drag grip and cannot be lifted. Moving blocks around under it works exactly as before, and a refused move leaves nothing to undo. Proven in the real-Electron suite: the file's bytes after the refused move, the reordered file after an allowed one, and the properties still recognised after a restart.
- **A save never writes over an edit made outside the app, and an edit you left behind is never dropped** — Two ways an edit could vanish with no copy and no message, both reproduced with a second app writing the same file. First: type in a note, and inside the second or so before Boojy Notes saves it, another app (Obsidian, a sync client) writes that file; the app's save landed over the outside version, and the change it then noticed on disk was taken for its own save's echo. The save now looks at the file before writing it, and if the bytes are not the ones it last read or wrote, nothing is written: the outside version keeps the note's name and your typing goes to `Title (conflicted copy YYYY-MM-DD)`, the same as when the outside change is seen first. Second: type in a note, switch to another one at once, and an outside write to the first lands before it has saved; the disk version was taken and your keystrokes were discarded, because the "keep both" rule ran only for the note on screen. It now runs for any note with unsaved edits; the copy appears as a row and the toast names it, and the editor stays on the note you switched to. Proven in the real-Electron suite and the unit tests beside the write handler and the file-system hook. One limit stays: two apps writing the same file within the same few milliseconds, faster than either can look before it writes, are not ordered by this; that case has not been seen and there is no complete answer to it short of a lock.
- **The top-row buttons work again while a note is open** — With a note open, Undo, Redo, the ··· and, with the sidebar hidden, the panel toggle, Search and New note could stop responding: the pointer never changed over them and a press dragged the window instead. The row the note's name sits in is what you drag the window by, and its draggable area was the whole row, buttons included, which on macOS put an invisible window-move layer over them. The draggable area is now only the stretch between the button groups. Dragging the window by the row still works.
- **A folder no longer turns white when you drag a note over it in Dark mode** — Once the note had passed over a folder, the row was left on the browser's own button grey, plainly visible on the dark sidebar and staying there until you hovered it. The drop highlight now puts back exactly what the row had before, and a folder row rests on transparent whatever happened to it. Alongside, the drag's colours are read from the theme on screen rather than the one at launch, so switching to Dark after opening the app no longer leaves a drag painting Light's greys.
- **Undo changes the note you are looking at, and no other** — Editing a note, opening a second one and pressing Cmd+Z undid the edit in the *first* note: the note off screen changed, its file was rewritten, and nothing on screen said so. Undo and redo now act on the open note alone — its newest edit, whichever notes were edited in between — and the note you are looking at is the only note either can change. Opening a note you edited earlier in the session gives you its remaining history back, and an edit in one note no longer discards another note's redo. Alongside: typing in one note and switching to another within a third of a second used to leave the second note with nothing to undo, because both notes' keystrokes were one step; each note's typing is now its own. History is still temporary — it starts empty each time the app opens — and still never brings back a deleted note or moves a file back to an old folder. Proven in the real-Electron suite and the unit tests beside the history owner.

## v0.7.0 — 2026-09-11

The first published release since v0.5.0 (2026-06-12). Everything in this section and in the
v0.6.1 and v0.6.0 sections below ships together in it: those two numbers were only ever the
`package.json` versions of local daily-driver builds installed from master on 2026-09-05, and

### Improvements
- **The macOS build is signed and notarised** — Every published macOS build before this one was unsigned: macOS said the app "could not be verified" on first open, and Settings → Updates could never install anything, because the updater refuses an unsigned app and the error was swallowed. From v0.7.0 the release pipeline signs with the Developer ID and notarises with Apple, so the app opens without a detour through System Settings and future releases install from Settings → Updates.
- **All six ATX heading levels open, edit and save as headings.** H4–H6 work through typed Markdown and slash-menu search while the initial menu keeps H1–H3. Imported heading spacing and optional closing markers are retained through text edits. The six-level type hierarchy keeps deeper headings readable beside body text.
- **Tables you can delete, enter and leave** — A table could not be removed from a note: Backspace under it deleted the paragraph below into the one above and left the table standing, forward Delete above it did nothing, the cell menu had no Delete table, and the smallest it could be shrunk to was one header cell. A table is now addressed as a whole, like a divider: Escape from a cell selects it (the same tinted band), Backspace or Delete removes it as one undo step, Enter opens a paragraph under it, and Backspace at the start of the paragraph below or forward Delete at the end of the paragraph above selects it first instead of stepping over it. The cell's right-click menu ends with Delete table, and the gutter grip can move a table like any block. The arrows walk in and out too: ArrowDown from the paragraph above lands in the first cell, the arrows move between cells at a cell's edges (wrapping rows), and ArrowDown from the last row leaves to the paragraph below. A new table is a small grid with square corners and one even border that grows with what you type rather than filling the column; past the column's width the columns share the space and wrap, the way browser tabs shrink, and only a table too wide to shrink any further scrolls sideways inside the note. The add-row and add-column controls are bordered boxes with a `+`, the way Obsidian draws them, that appear as the pointer moves past the grid's right or bottom edge; the teal ring on the focused cell is gone (the caret is the signal), a new column no longer writes `Col 3` into the header, and the cell's right-click menu is rebuilt on the note menu's grammar: it opens under the table in line with the column you clicked rather than wherever the pointer was, carries a glyph per item and sentence-case labels in the app's own face (it used to fall back to the browser's serif), and takes the arrow keys, Enter and Escape. Its Align left, centre and right items are gone: a table that already carries an alignment in its Markdown still shows it and keeps it, but the app no longer offers a control to set one. Proven in the real-Electron suite and the unit tests beside the table, its menu and the block rules.
- **Type `**bold**` and it turns bold** — Formatting no longer needs a selection and the toolbar: type the Markdown you already know and the run becomes its element the moment the closing marker lands, with the caret after it so the next character is plain. `**bold**`, `*italic*`, `` `code` ``, `~~strike~~`, `==highlight==` and `***both***`, plus the underscore forms `_italic_` and `__bold__` (saved as `*italic*` and `**bold**`, the form the app writes). The file holds exactly the Markdown you typed, so nothing about your notes changes, and Cmd+Z takes the typing back as it always has; literal stars are `\*`, shown as written. Prose that merely contains the markers (`2 * 3 * 4`, `a ** b`, `snake_case_name`) is left alone, and the conversion never fires inside existing bold, a link, a code block, a table cell or a callout. Proven in the real-Electron suite and the unit tests beside the matcher.
- **The selection toolbar waits until you have finished selecting** — It used to appear and slide about under the pointer while a selection was still being dragged. It now appears when the mouse is released, or a beat after a keyboard selection (Shift+Arrow, Cmd+A) stops changing, and hides at once when the selection collapses. Its buttons are Lucide icons like the rest of the chrome (the styled letters are gone), a pressed format shows as the glyph in the accent rather than a tinted box, pressing one no longer makes the toolbar blink away and back or slide sideways as the text changes width, and resting on one shows its name and shortcut above it (`Bold ⌘B`, `Strikethrough ⇧⌘S`; `Ctrl+` on Windows), out of the way of the selected text.
- **The slash menu shows the shortcut you could have typed** — Each row of the `/` menu now carries its typed Markdown shortcut in muted type on the right (`#` beside Heading 1, `-` beside Bullet list, `[]` beside To-do list, `>` beside Quote, `---` beside Divider), the way Notion's does, so the menu teaches the faster route while you use it. Table and Image, which no Markdown shortcut makes, gain quick keys of their own: three pipes (`|||`) on an empty line makes an empty table at once, the way `---` makes a divider, and `![]` followed by a space opens the image picker, the picture-box cousin of `[]` for a to-do. Typing `![alt](url)` in full still works as before. Two rows are renamed in plain words: Blockquote is now Quote, and Checkbox is now To-do list, which reads with Bullet list and Numbered list as the three kinds of list. The row glyphs are drawn a step heavier, matching the sidebar's chrome, so they hold their own beside the label and the hint. Nothing about what the rows insert has changed.

### Bug Fixes

- **A vault holding an indented quote opens again** — A `> quote` line indented under a list item, ordinary Obsidian output, sent the parser into a loop: the vault could not be opened at all, and the same file arriving through the watcher froze a running app. The line now reads as the quote it is, keeps its indent on disk, and the parser always advances.
- **Code stays aligned with its caret after blank lines.** Empty lines in the visible code layer now keep their height, matching the editable text underneath. Clicking a character after a blank line edits that character, with or without syntax highlighting.
- **Imported fenced code stays literal through editing and saving.** Tilde fences now open as code, so Markdown examples inside them are no longer interpreted or rewritten as headings, tasks, callouts or tables. Imported backtick and tilde boundaries retain their marker, length and whitespace, including empty and unclosed blocks; a longer matching closing fence is recognised correctly. Intentional content edits lengthen a fence only when needed to keep the edited text inside it.
- **Numbered sub-lists stay nested in other Markdown readers.** The editor and file writer now share numbering and indentation rules, including grandchildren, mixed lists and multi-digit parent numbers. Structural edits renumber affected sequences and keep valid depths; text-only edits preserve imported markers, and Undo restores their original form.
- **The gutter grip lines up at every UI scale, and can lift a table** — With the UI scaled up (Cmd+Plus), the six-dot grip beside a hovered block drifted downward the further into the note you hovered: 3px on the first block and about 35px three blocks down at 120%, and more at 133%. The browser reports every measured position multiplied by the scale, and the grip's own position was then scaled a second time on paint; the same doubling moved the translucent copy and the drop line during a drag. Every measured distance is now divided by the scale once, and the grip, the copy and the drop line sit exactly where they do at 100%. Separately, the grip beside a table could be seen but never pressed: the table's invisible row-selection strip along its left edge sits exactly where the grip is drawn and was stacked above it, so every press selected the header row instead. The grip now stacks above the strip and a table drags like any other block; the strip keeps the rest of its height for selecting rows.
- **Saving a note keeps the file's permissions** — A note you had made private with `chmod 600`, or a vault a group may only read, came out of every save with ordinary `644` permissions: the crash-safe save writes a fresh temp file and renames it over the old one, and the fresh file had the default permissions, not the old file's. A save now gives the file exactly the permission bits it had, a rename in the app carries them to the new name, and a note that never existed is made the way any new file is on the machine (the umask), never from a temp file a crash left behind under the same name, which until now handed its own permissions to the new note. The app's own `config.json` and `settings.json` follow the same rule. Creation date and Finder tags are still not carried across a save; that is a separate decision, recorded in the backlog. Proven in the real-Electron suite and the unit tests beside the write path.
- **A code block, callout or table chosen from the slash menu is where you type next** — Choosing Code block, Callout or Table from the `/` menu made the block, then put the caret in an empty paragraph underneath it, so the block you asked for stayed empty and the lines you typed became paragraphs under it (two lines of code, two paragraphs). The block now takes the next keystroke: Code block in its text, Callout in its title, Table in its first cell. Divider, Image, File attachment and Embed note have nothing to type into and still open a paragraph under themselves. Alongside, Escape or the arrows out of a code block or callout now enter a neighbouring callout or table rather than leaving the caret where it was. Proven in the real-Electron suite and the unit tests beside the slash commands and the focus effect.
- **Search opens the note it highlights, and a right-click menu opens under the pointer** — Two things that should have been beyond doubt. In Search (Cmd+P), when any result sat inside a folder, the row shown as highlighted and the row Enter opened could be two different notes, and the arrow keys jumped about the list rather than walking down it: the list was drawn in match order but the highlight followed a second, folder-grouped order that nothing on screen showed. There is one order now, the one you see, on desktop and in the mobile list alike; the mobile list shows each result's folder beside its title instead of under folder headings. And a right-click on a link, a code block, an image or an attached file opened its menu a long way from the pointer (about 280px to the right, and further off the more the note was scrolled), because the editor column's fade-in left it with a transform that every fixed-position menu inside it then measured itself from. The fade is opacity alone now and the menus open where you clicked. Proven in the real-Electron suite.
- **Typing in front of a link, or after a space in the title, lands where you typed it** — Two everyday keystrokes went astray. On a line that begins with a `[[wikilink]]`, pressing Home (or arriving from the title with Enter) and typing put the character *inside* the link, so `Y` in front of `[[Review note]]` was saved as `[[Review note|YReview note]]`: the link's alias, not your text. The end of a link was fixed in September; its start now follows the same rule, and text typed there is prose in front of the link (one step into the link still edits its alias). And a space typed at the end of the title, then a pause long enough for the note to save, vanished under the caret: a filename cannot end in a space, so the file became `Meeting.md`, the app painted that name back into the field you were still typing in, and `notes` typed next made `Meetingnotes`. The real name still reaches the sidebar and the file at once; the field you are typing in keeps its trailing space, so the words that follow land where you meant them. Proven in the real-Electron suite and the unit tests beside the caret helpers and the title hook.
- **A soft break never turns into a heading, a list or a rule** — Pressing Shift+Enter inside a paragraph and then typing a line that begins like Markdown structure (`# bar`, `- bar`, `1. two`, `---`, three backticks) looked right on screen, but the file said otherwise: on the next open, in Boojy Notes and in every other Markdown app, the line had become a heading, a list item or a horizontal rule, `---` turned the line above it into a heading, and a soft-broken fence swallowed the rest of the note into a code block. The same happened to a line under a list item, and two plain lines pasted into a heading came back as a heading and a paragraph. Such a line is now saved with its marker escaped (`\# bar`), the standard Markdown escape every reader shows as the plain character, so the file means the one paragraph you typed; after a reopen the backslash is shown as written, like any escape. A file that already holds a heading tight under a paragraph is read as that and never rewritten. Alongside: a link written as `<https://example.com>` grew a stray `;` on every edit and linked to the wrong address, a bare address ending in `&` did the same, an address inside a link's text became a second link and scrambled the link on save, and one inside a `[[wikilink]]` broke the link's markup; bare addresses are now linked only in ordinary prose, read as written. Proven in the real-Electron suite and in the unit contracts, which take the escaped lines through the screen and back and through an independent Markdown parser.
- **Editing a paragraph rewrites only what you typed** — Four things a paragraph could hold were changed by the act of editing it. Pasting a single line with formatting (a bold word, a link from a browser, a page copied from Word or Docs, or formatted text copied inside the app) split the paragraph into pieces, scrambled the link and lost everything after the pasted word from the file; it also wrote a non-breaking space where the ordinary space before the paste had been. A zero-width space the file itself held was deleted on the first keystroke in its paragraph, because the editor mistook it for the invisible marker it parks the caret on after a link. A space that was the only thing between two asterisks or backticks (`a * * b`) vanished with them. A `↗` inside a link's text was deleted, because the editor draws the same arrow as the link's icon. And an explicit link whose text is its own address, the form Notion exports bookmarks in, was collapsed to a bare address, which is not a link in strict Markdown. A pasted line now lands inline with its formatting and plain spaces around it; the caret marker is a marked element the file's own bytes can never be confused with; a formatting span keeps whatever it holds; the icon is told from the character; and only the editor's own automatic links are written bare. Proven in the real-Electron suite and a new unit contract that takes every text block of the preservation corpus through the screen and back, byte for byte.
- **A key acts on what you are looking at, and on nothing beneath it** — Several keys reached two places at once. Enter in a delete confirmation deleted even with Cancel focused, so the "safer" default button protected nothing; Cmd+Z while typing in the search field, or in a note's rename field, took a word out of the note behind it; Escape on a context menu, a rename field or the search palette also hid the sidebar when the window was narrow enough for it to float; Cmd+N and Cmd+P worked through Settings, making a note or opening search behind it; Cmd+K opened the search palette and the link editor together; and Rename from a note's ··· or right-click menu opened nothing, because the closing menu took focus back from the field a frame later (double-click always worked, which is why it went unnoticed). The rule now is that the closest surface owns the key: Enter presses whichever button holds focus and Tab stays inside the dialog; a text field keeps its own undo; Escape closes only the topmost layer; no shortcut runs while a dialog or menu is open, and each closes itself on Escape; Cmd+K is the link editor and Cmd+P is Search (Boojy Notes has a search, not a command palette); and a menu that closes leaves focus wherever it has gone since. Alongside, a typed `#tag` keeps the space that ends it (`#alpha beta` was becoming `#alphabeta`), and Enter after a tag typed in full, or one nothing matches, starts a new paragraph rather than "completing" the tag: the suggestion menu takes Enter only when it offers a real completion or you have arrowed to one. Escape in the link editor's field now closes it. Proven in the real-Electron suite and the unit tests beside the shortcut handler, the focus trap, the confirm dialog and the tag menu.
- **Find → Replace changes the note you are looking at** — Replace and Replace All rewrote the note in the file but not on screen: the paragraph kept the old text, the match counter did not move, and the next keystroke in that paragraph saved the old text back over the replacement. Replace now edits the matched text where it is on screen and the paragraph is read back from that, as it is after any keystroke, so the screen, the note and the file agree at once and the counter moves on to the next match. Alongside: Replace edits the match you can see (before, the second visible `docs` could replace the one inside a link's address), the replacement is plain text (`$&` was treated as a pattern), and a match inside a table cell, a callout or a code block is found and highlighted but left alone by Replace. Proven in the real-Electron suite and the unit tests beside the find bar.
- **A character typed after a link is never lost** — Typing ` after` straight past a freshly typed `[x](https://a.b)` lost the `a` (or the space): the link's styling repainted the paragraph from a copy of the note that was one keystroke behind the screen. Every repaint of a paragraph now takes the text from the latest keystroke, so nothing typed inside that window is painted over; the same rule closes the character loss seen on the dev server after editing a title. Alongside, the completed `[[wikilink]]` no longer paints its paragraph by hand; it repaints like every other change. Proven in the real-Electron suite and the unit test beside the block.
- **Tables, callouts and code blocks are real editable blocks** — Each of the three kept its text in a field of its own with its own rules, and each rule lost something. A line break inside a table cell (Shift+Enter, or a pasted line) was written into the file as a second line, so the table came back broken on the next open: the header survived and that row and every row below it read as a paragraph, here and in every other Markdown app. Clicking into a callout's body and out again, without typing, saved the body with its formatting stripped: every `**bold**`, `[[link]]` and backtick gone. Enter at the end of a code block did nothing, and a code block whose first or last line was blank lost those lines at the first keystroke; each character typed into one was its own undo step and repainted the whole note. And text typed into a table cell was lost the moment a row or column was added, removed or moved from the cell's own right-click menu, because the cell had never been asked for it. The three fields now behave like any paragraph: what you type reaches the note at once, with formatting kept; Cmd+Z takes back a burst of typing rather than a character; a row or column operation works on the table as it is, typed text included; a line break inside a cell is saved as `<br>`, which GitHub and Obsidian show as a line break in a cell, and Enter in a cell moves down a row (adding one after the last) instead of breaking the cell; Enter or Shift+Enter in a callout's title moves to its body. Alongside: changing a callout's type now repaints its icon and title at once rather than at the next edit. Proven in the real-Electron suite and the unit tests beside the three blocks, the serializer and the shared field hook.
- **A note renamed or moved outside Boojy Notes stays the same note** — Renaming a note's file in Finder, moving it into another folder, or moving a whole folder, while you had unsaved edits to a note in it, brought the old file back: the app saw the old name disappear, kept your edits because they were unsaved, and saved them as a fresh file under the old name, or a fresh copy of the old folder, beside the renamed one, which kept the text from before your edits. The app now recognises the file by the identity the disk gives it (its inode, which a rename keeps), so the note follows its new name and folder in the sidebar and the editor, your unsaved edits are saved at the new path, and a note you were not editing is left exactly as the rename made it, not rewritten. A rename the app cannot trace, such as a copy-and-delete or a move to another disk, is still treated as the delete it looks like, which keeps your edits under the old name and loses nothing. Proven in the real-Electron suite and the unit tests beside the index and the file hook.
- **One character typed into a new note is never lost** — A new note starts as a draft, which became a real note only once what you typed had reached the app's state, a third of a second after the keystroke. Typing one character (a name, or the first letter of the body) and clicking another note, or pressing Cmd+Q, inside that window deleted the draft with the character in it, with no undo; typing more than one character was safe, because a second keystroke published the first at once, which is why it went unnoticed. A draft now becomes a note at the keystroke that first gives it text, so switching notes or quitting at any moment after it keeps the text and the file. Alongside: while the app was writing your edits as a conflict copy (a note changed outside Boojy Notes while you had unsaved edits to it), switching apps or quitting inside that write's few milliseconds could still write your version over the outside edit; the note is now treated as conflicted from the moment the outside change is seen, and a save that lands during the copy's write waits for it. Both proven in the real-Electron suite and the unit tests beside the two hooks.
- **A note or folder named in Finder keeps its name** — A folder made in Finder called `Work: Client`, or one with a space at the end, and a note that already existed as `Why?.md`, were renamed by the app's first save: the characters the app replaces when it makes a new file were replaced in names that were already on disk, so the note was written into a new `Work_ Client` folder and removed from the original while the sidebar still showed it in `Work: Client`, `Why?.md` became `Why_.md`, and dragging such a folder into another renamed it on the way. A name the disk already holds is now kept exactly through every save, move and restart; only a name you type in the app, a new title or a new folder name, is adjusted so the file can exist. Proven in the real-Electron suite.
- **A change made outside Boojy Notes is never mistaken for the app's own save** — The app tells an echo of its own save from an outside change by the bytes: a file that still holds exactly what the app last wrote is an echo, whenever the event arrives. That memory was never cleared, so once you had changed a note outside the app, changing it *back* (checking out in git, Undo in Obsidian, a restore from a sync client or Time Machine) was taken for an echo and ignored, and the next save wrote the outside version over your revert; a note deleted in the app and put back from the Trash was ignored the same way and stayed missing until a relaunch. A file deleted outside the app within 1.5 seconds of the app's own save of it was ignored on the clock alone and stayed in the sidebar. The watcher now drops only an event it can trace to the app's own operation: the memory of a save ends the moment the file holds anything else or goes away, and a delete the app makes itself is claimed once and matched to the one event it causes, so an outside delete is real however soon it lands. Proven in the real-Electron suite: a revert to the app's own bytes, an outside delete right after a save, a file deleted and restored with identical bytes, and a note put back from the Trash.
- **A move, a block drop or an outside change can no longer be undone by your own typing** — Note state had two owners: the editor's keystroke buffer, which runs a third of a second ahead of the app's state while you type, and a raw state setter that four operations used directly. Anything those four did inside that window was quietly reverted when the buffer was published: a note dragged into a folder within a third of a second of a keystroke was written back at its old location; a block dropped in that window snapped back to its old place in the file; a file deleted outside Boojy Notes while you were typing came back as a fresh file, a keystroke was lost, and every note in the vault was rewritten; and after Settings → Storage → Change, the edits you had just made were written into the new vault, or lost. Every change to note state now goes through one owner, which applies it on top of whatever is still in the keystroke buffer. Alongside: undo is the editor's, so pressing Cmd+Z after moving a note undoes the typing and leaves the file where you moved it (before, it moved the file back); undo never brings back a note you deleted or a note from a vault you have left (before, either was written as a new file into whichever vault was open); changing the vault first saves the old vault's pending edits, then leaves it, then opens the new one, so nothing crosses over; and a version already saved on losing focus or quitting is not saved a second time when the buffer catches up. Proven in the real-Electron suite: undo after a move, a block drop inside the typing window, an outside delete while typing, and a vault switch with unsaved edits.
- **An edit that reaches across two blocks can no longer crash the editor or corrupt the note** — Pressing forward Delete at the end of a block, cutting a selection that spanned two blocks, or pressing Shift+Enter over one, left the browser to merge the blocks itself; the editor's next change then met a page it had not made and gave up with "Something went wrong", and until then a save could write the merged text twice. Cmd+B over such a selection made both blocks bold on screen but saved only the first; a URL pasted over one landed outside every block; a selection dragged from a paragraph into a table, then Backspace, removed the table from the screen but not from the file; and a Delete or Backspace beside a code block could swallow it. Every edit whose reach crosses a block boundary is now made by the app: forward Delete at the end of a block joins the next block (or selects a divider or image first, as Backspace from below does), a cut, a typed character, Enter, Shift+Enter or a paste over a selection spanning blocks replaces it within the first block, Cmd+B and the other formatting shortcuts format each block within itself, and a Delete or Backspace beside a code block, table or callout changes nothing. A selection that reaches from text into a table, callout or code block is refused rather than guessed at. — Notes are written one after another, and a note's "needs saving" mark was cleared when its write came back, whatever had been typed in the meantime. An edit that landed while that write, or the writes of other notes ahead of it in the same save, was in flight was marked and scheduled as usual, and the save it scheduled then found nothing to do: the newer text stayed on screen and the older on disk until the app lost focus or quit, and a save that started with several notes wrote the later ones as they were when it began. A single save takes about ten milliseconds, so the window was small; dragging many notes into a folder while typing widened it to seconds, and the typed text reliably failed to reach disk. The mark is now cleared only by a save of exactly the version the note holds, and every note is read as its own turn comes. Proven in the real-Electron suite with a 150-note move and a keystroke during it.
- **Tab keeps your place in a list** — Pressing Tab or Shift+Tab on a list item indented it correctly but sent the caret to the start of the item, so the next characters landed in front of the text and the next Enter split the item in the wrong place. The caret now stays exactly where it was, at the end or in the middle of the text alike.
- **Enter accepts a tag suggestion** — Typing `#rev` with `#review` in the vault and pressing Enter on the suggestion split the block in two and left `#rev` as it was; only a click on the suggestion completed it. Enter now completes the tag in place, the completed tag shows at once, and typing continues after it. Underneath, a key that a suggestion menu has already taken never reaches the editor's own handlers, for the tag and link menus alike.

A name the app creates never starts with a dot now: it becomes `_env`, `_archive`, shown at once, the same way other characters a filename cannot hold become `_`. A folder named `attachments`, the app's attachment store, becomes `_attachments` for the same reason. Nothing already on disk is renamed.

The empty forms now open as the blocks they are, the bare markers other editors write (`-`, `1.`, `#`) included, without changing the file's bytes.

- **The wordmark reads in Dark** — The "Notes" mark in the sidebar's top row was drawn from one black asset in both themes, so in Dark the "otes" sat near-black on the dark ground and only the cyan N showed. Each theme now draws the mark in its own text colour, with the N unchanged; Light is imperceptibly different (the ink is now exactly the text colour rather than black at 92%).
- **Settings → Updates is readable in both themes** — "Restart & Update", shown once an update has downloaded, was white text on Dark's pale accent, about 1.7:1; the auto-update switch's knob was a white dot that vanished on Light's pale off-track and on Dark's pale accent when on. The button and the knob now take the colour each theme reserves for text on its accent, and the off-state knob is drawn in a visible grey.
- **The hidden-sidebar toggle no longer sits on the note's name** — With the sidebar hidden, the show-sidebar button in the top-left corner was drawn over the first letters of the note's name on macOS, at wide and narrow windows alike, because the name kept clear of the button as if it sat where it does on the web rather than right of the traffic lights. The name now starts past the button with the same air at every width; nothing else in the layout moves.
- **A task's checkbox sits on its first line** — When a task wrapped to two or more lines the box slid to the vertical middle of the text, so it no longer read as the start of the item. It now sits on the first line, level with where a bullet or a list number would be, whatever the item's length.
- **The installer is half the size** — Every build packed the previous build's own app and installer into the new one, and copied the source of every library the app is built from beside the bundles that already contain them: the app archive was 345 MB with 5,800 files, the DMG 244 MB. Installers now build into their own directory and the archive holds only the built app, 1.2 MB in 18 files; the DMG is 118 MB, which is the size of Electron itself. Nothing about the app changes; the update check and every other desktop feature were verified in the packaged build.
- **A folder stays when its last note leaves** — Dragging the only note out of a folder, or moving it with Move to, quietly deleted the folder it came from; now the folder is a folder until you delete it yourself.
- **Closing the window no longer breaks the app underneath** — On macOS, after Cmd+W the app kept running with no window, and a note changed on disk or a finished update check then threw an error in the background. Both now wait; a click on the Dock icon brings back a window with spell check and its context menu, which the reopened window used to lack.
- **A missing notes folder is not silently replaced** — If the folder you chose was not there at launch (an unmounted drive, a folder moved in Finder), Boojy Notes created an empty one in its place on the boot disk and put new notes there. It now opens the vault empty, refuses to save with the ordinary "Failed to save" message, and creates nothing; choose the folder again in Settings → Storage once it is back.
- **Settings survive a crash mid-save** — The app's own config and settings files were written in place, so a crash at the wrong moment could leave a torn config, which the next launch read as "no vault chosen" and opened the default folder instead of yours. Both are now written the way notes are: to a temp file first, then swapped in.
- **Links open in your browser, never in a second window** — A web link (the boojy.org line in Settings, a link in a note opened with the middle button) opened a bare second app window; it now goes to the system browser, and nothing can navigate the app window away from the app. Attachment paths a note names are opened only when they lie inside the vault.
- **A vault inside a hidden folder is watched** — A notes folder under a dot-directory such as `~/.notes` was never watched for outside changes, with no error; edits made in another app did not appear until a restart. They now appear as they do for any other folder.

## v0.6.0 — 2026-09-05 (daily-driver build; published as part of v0.7.0)

### Bug Fixes
- **Changing the notes folder no longer keeps the old vault's folders** — Switching to another vault in Settings merged its folders into the previous vault's list, so phantom folders lingered until a restart. The new vault's directories now replace them.
- **Paragraphs are paragraphs: blocks now follow Markdown structure, not source lines** — A block used to be one line of the file. Two paragraphs typed with Enter were written as two adjacent lines, which every other Markdown reader (Obsidian in reading view, GitHub, Pandoc) joins into one paragraph; and a paragraph written over two lines in another app opened as two blocks. Now adjacent lines of one paragraph are one block with a soft break between them, Enter starts a new paragraph and writes the conventional blank line, Shift+Enter keeps you in the same paragraph, and a plain line directly under a list item belongs to the item, as it does everywhere else. One blank line between paragraphs is spacing rather than a row; every further blank line is still an empty row you can see and delete. Nothing is stored that the file does not say, no file is rewritten by opening it, and editing one block leaves the rest of the file byte for byte as it was, including blank-line runs, list markers, quote lines, hard breaks and the final newline; proven by the byte-sensitive preservation corpus and a read-only pass over two real vaults with no unexpected change. Pasting plain lines now keeps them together as one paragraph; a blank line in the clipboard still starts a new block. One narrow gap stays on record: a paragraph typed directly after a quote is written on the next line, which other readers fold into the quote, because a quote's lazy lines cannot be stored inside the block without changing their bytes on save.
- **Shift+Enter is a line break inside the paragraph, and it stays one** — A line break inside a paragraph reached the file correctly as a plain newline, but the editor never drew it again after a repaint: switch notes and come back, or undo, and "one⏎two" read "one two" on screen while the file still said two lines. Newlines inside a block now render as visible line breaks (a trailing one keeps its empty line reachable), Shift+Enter inserts one on purpose in paragraphs, list items and quotes, and the caret counts a break as one character so typing after it lands where it shows. In a heading Shift+Enter acts as Enter, because a heading has no second line. This is the foundation for the paragraph model that follows; the file format is unchanged.
- **Deleting a folder or several notes asks first, and says what will happen** — On desktop, "Delete folder" and "Delete N notes" acted at once with no confirmation. Both now ask, in words that describe the real action: `Move 12 notes to the Trash?`, with a note that the folder on disk and any file in it that is not a note stay exactly as they are. Nothing else changes: a single note still goes to the system Trash immediately, now with a quiet "moved to the Trash" toast; a folder with no notes is removed from the sidebar without a prompt because nothing on disk changes; the web build still confirms every deletion because there it is permanent. Proven in the real-Electron suite with a folder holding a note and an unrelated `budget.txt`: after confirming, the note is gone from the vault and the text file and the folder remain.
- **Typing after a completed `[[wikilink]]` is prose again, and link tooltips behave** — Picking a note from the link suggestions put the caret inside the rendered link, so the next keystrokes became part of it and the file read `[[Beta|Beta after]]`. The caret is now parked just outside a link (at the end of a block or before following text) on an invisible anchor that never reaches Markdown; bold and italic still extend as before. Separately, every hover over a link raised an error and left its half-second timer untracked, so the tooltip could appear after the pointer had already gone. Hovering is quiet now, moving off before the delay shows nothing, and resting on a link still shows its target. Both are proven in the real-Electron suite, the first by the Markdown on disk.
- **A note's title is its filename, and you see the real one straight away** — Moving a note into a folder that already held a namesake gave the file a `-2` suffix on disk while both rows still read the same name, and every later save of that note bounced its file between `-2` and `-3` because the uniqueness check counted the note's own file as a collision. Renaming to a name a filename cannot hold (`Notes: a/b?`) showed that name until a restart revealed `Notes_ a_b_`. Now the save reports the name the file actually got — suffix, replaced characters, trimmed edges, `Untitled` for a blank name — and the sidebar row and the editor's title adopt it at once, keeping the caret if you are still in the field; a restart never reveals a title you had not already seen. Three more naming faults fixed on the same path: clearing the title used to name the file `_.md`; renaming a note to the same name in a different letter case deleted its file on macOS; and a file that appeared on disk without the app noticing could be written over. Proven by a new real-Electron journey covering move, repeated saves, rename, restart and leftover temp files.
- **"Most recent" now means most recently modified, and opening a note never moves it** — Clicking a note used to promote it to the top of the list at once, so the rows reshuffled under the pointer; a double-click rename then renamed the row that had moved into the clicked position, and the wrong file was renamed on disk. Order now comes from the file's modification time, with edits made in Boojy Notes counted the moment they happen and edits made in other apps picked up live. Opening, selecting and reading are side-effect-free, and the order is the same after a restart. The last-opened timestamps kept in `localStorage` are no longer read or written.
- **Quitting or switching apps no longer rewrites notes you had already saved** — Every note touched during a session was written again on quit and on every window blur, whether or not it had changed since its last save. Each got a fresh modification time in write order, so "Most recent" came back in a different order after a restart and anything watching the folder saw phantom edits. A note now leaves the quit-flush set as soon as its newest content is safely on disk; a failed write keeps it there and is retried, and a flush cancels the pending debounced write so it cannot fire behind it. Text typed in the last third of a second before Cmd+Q is still saved.
- **Undo now changes what you see** — Cmd+Z after plain typing reverted the file on disk but left the old text on screen, so undo looked broken and, until the next keystroke wrote the stale screen back over the file, the page and the file disagreed. An undo within a third of a second of typing was also cancelled out when the pending text commit fired. Undo and redo now repaint immediately and cancel that commit. This is the first fix proven by a new real-Electron core-journey suite (`pnpm test:electron`) that runs the built desktop app against a throwaway vault and checks that the editor and the Markdown on disk describe the same note.
- **Desktop: caret no longer jumps to the top of the note, and keystrokes are no longer lost, mid-typing** — Every save Boojy made was echoed back by the file watcher, and the "ignore my own write" window was a separate timer per save on one shared list, so two saves landing 1.15–1.5s apart (a normal pause-type-pause rhythm) let the second echo through. Boojy then treated its own file as an external edit, rebuilt the note from disk, dropped the caret at the start of the first block and discarded anything typed since that save. The window is now one timer per file, reset by each write.
- **Pasting into a checkbox no longer turns it into a paragraph** — Pasting text that carried a line break into an empty checkbox, or at the start of one, replaced the checkbox (and any bullet, numbered item or heading) with plain paragraphs. Copying a whole line from most apps brings its line break along, so this looked random. A block now keeps its type, checked state and indent when plain text is pasted into it; only pasting Markdown with structure of its own, such as `## Heading` or `- [ ] task`, into an *empty* block adopts that structure, and pasting structure into a block that already has text puts the new blocks beside it rather than changing it. One trailing line break on the clipboard is treated as incidental and pastes inline; a deliberately copied blank line still comes through. Two related fixes ride along: a paste that only changed a block's text could reach the file but never the page (the next keystroke then wrote the empty line back over it), and copying the text inside a single list item no longer carries the list with it, so pasting it onto a blank line gives just the text. Structure still travels when the copy spans two or more blocks.
- **Hold-and-drag block reorder works on every note, not just the one open at launch** — The pointer handler that starts a drag reaches the editor through a context whose value is fixed when the app mounts, and it looked the pressed block up in whichever note was active at that moment. On any note opened later the lookup found nothing and the hold silently did nothing (the "Hold and drag to reorder" tip never appeared either). It now resolves the current note at press time. Keyboard reordering (`Cmd/Ctrl+Shift+↑/↓`) was unaffected.
- **Cancelling a block drag can no longer write the dragged blocks into a different note** — Escape and window-blur cancel a hold-and-drag through listeners registered once at startup, and the cancel routine restored the original block order into whichever note was active when that listener was captured — potentially not the note being dragged, if Settings had been opened in between. The drag now records the note it started in and every write it makes (live reorder, cancel-restore) targets that note; a note deleted mid-drag is left alone rather than recreated. The same stale capture made Cmd+P un-collapse the sidebar instead of revealing it once the window had narrowed into overlay mode; the shortcut handler now reads its actions fresh on every keystroke.
- **Clicking a `#tag` in the editor filters the sidebar again** — The click handler existed but stopped being passed to the editor when the pane layer was removed on 2026-08-18, so tags rendered as clickable and did nothing. Clicking one now opens sidebar search on that tag, as it did before.

It now uses the already-imported dialog.
- **Web no longer shows an "Import files here" folder action that did nothing** — Import is a desktop file-picker flow; the menu item now appears only in the desktop app.
- **The crash screen's "your notes have been backed up" is true again** — The error boundary writes the in-memory note store to `boojy-error-backup` in local storage on a crash, but it was mounted without the reference it needed, so the backup never ran while the message still claimed it had. It is wired up now.
- **Onboarding no longer promises "Swipe right for notes"** — There is no swipe gesture in the responsive layout (only the bottom sheet dismisses by swipe), so the mobile hint described something the app cannot do. The sequence is now the three hints that are true everywhere: slash commands, wikilinks, tags.
- **Editor font size is remembered** — The Settings → Appearance size control worked, but the value lived only in memory and came back as 15 on every launch. It now persists alongside the other appearance preferences.
- **Onboarding no longer advertises the removed split view** — The progressive hint sequence no
  longer tells established desktop users to press the retired split-view shortcut.
- **Crash fallbacks use the active theme correctly** — Error boundaries now receive valid
  background and error-colour tokens instead of references to theme roles that do not exist.
- **Auto-update can be toggled from the keyboard** — The desktop Settings control is now a real
  accessible switch with a stable hit box and announced checked state.
- **Settings close button has a meaningful accessible name** — The existing `×` control is
  unchanged visually, but screen readers and voice control can now identify it as “Close settings.”
- **Sort-menu focus no longer gets lost** — Escape now closes the note-order menu and returns
  focus to its trigger. Tab closes it without cancelling the browser's normal focus movement,
  instead of leaving keyboard focus stranded on the document body.
- **Failed disk saves keep retrying** — If Electron cannot write a note, Boojy now keeps that note
  in its dirty set and retries every five seconds until the write succeeds. The first failure is
  reported without repeating the same notification on every retry; closing the app still uses the
  existing final flush path.
- **Slash commands reliably start at Heading 1** — Opening `/` no longer lets a stationary pointer accidentally select whichever lower menu row appears beneath it. Keyboard selection starts at the first command and changes only after an arrow key or real pointer movement.
- **Checkboxes update immediately** — Checking or unchecking a task now repaints its tick and strikethrough at once instead of waiting for Enter or another structural editor change.
- **Menus can no longer run off-screen** — The note-actions ··· menu used to open past the right edge of the window, and a slash menu near the bottom ran below it. All context/slash menus now share one placement rule: follow the anchor, keep an 8px margin from every edge, flip to the other side of the anchor when needed, and clamp as a last resort.

Boojy now reads each file's modified time, so tied results come out newest first.

## v0.5.0 — 2026-06-12

### Bug Fixes
- **Note titles show immediately after launch** — Reopening the app restored your last note with a blank title until you switched away and back. The restored session rendered before the notes finished loading from disk, and the title field never re-synced when they arrived; the disk load now signals the editor to re-sync, in both single-pane and split view.
- **Opening a folder of notes no longer leaves any trace in it** — The note ID index (`.boojy-index.json`) used to be written into the notes folder itself on every scan, so pointing the app at an Obsidian vault or any git-tracked folder dirtied it on first launch. The index now lives in the app's own data directory (one file per vault); an existing in-vault index is migrated over once and removed, and the index is only rewritten when it actually changes.
- **Split-pane editing can no longer lose keystrokes on quit** — Typing in one pane and then the other within the same fraction of a second, then quitting, used to flush only the second note's edits to disk. The quit/blur flush now tracks every note edited since the last flush and writes them all.
- **Saves now survive power loss, not just crashes** — The atomic write fsyncs the temp file before renaming it over the note (and best-effort fsyncs the directory), closing the window where a power cut just after a save could leave the note as zeroed bytes even though the rename had committed.
- **Turning sync off stops a sync that's already running** — A sync in flight when you flipped the toggle off used to run to completion, pushing and pulling notes after you'd asked it to stop. It now checks at every step and bails as soon as sync is disabled, without applying pulled notes to local state.
- **Opening notes never rewrites them on disk** — Files with YAML frontmatter (e.g. an Obsidian vault's `tags`/`aliases`/`created` properties) used to be silently rewritten the moment the app read them, stripping all frontmatter and re-serializing the body. Reading is now strictly read-only: third-party frontmatter survives untouched and shows as the collapsible frontmatter block; only true legacy Boojy files (Boojy-shaped `id:` in frontmatter) still migrate, and only when you next edit them. Guarded by new regression tests asserting files stay byte-identical after a read.
- **Saves are now crash-safe** — Notes (and the ID index / folder metadata) are written to a temp file and atomically renamed into place, so a crash or power loss mid-save can no longer truncate a note; you keep the previous version instead. Renaming a note now writes the new file *before* deleting the old one — a crash in between leaves a recoverable duplicate, never a missing note.
- **Imported markdown survives saving unchanged** — Three round-trip fixes for files written by other tools: code blocks containing a lone ```` line are no longer corrupted on save (the fence now grows past the longest backtick run in the content); numbered lists keep their actual numbers instead of all collapsing to `1.`; and standard `![alt](url)` images keep their syntax and alt text instead of being rewritten to `![[url]]` wikilinks (a custom width uses the Obsidian-style `![alt|350](url)` suffix). All three are locked in by new round-trip guardrail fixtures.
- **Quitting no longer loses your last keystrokes** — Typed text sits in two short debounces before reaching disk, and the app used to quit without waiting, silently dropping anything typed in the last ~1 second. The window close (Cmd+W or quit) now waits for a flush of pending edits to disk — capped at 2 seconds so a hung renderer can never trap you in the app — and edits also flush whenever the window loses focus.
- **Desktop is local-only unless you opt in to sync** — Cloud sync on desktop is now off by default and controlled by a per-device "Sync on this device" toggle in Settings → Profile. Previously, a Supabase session silently restored from an earlier run would start a full sync 500ms after launch — and a stale cloud copy could overwrite newer local notes. Signing out now also clears leftover sync metadata (last-sync marker, version map, dirty queue), which used to skip the first-sync confirmation and re-push notes unprompted on the next sign-in.
